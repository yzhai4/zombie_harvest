# 尸潮农场开发路线

这份路线把玩法目标、性能验收和引擎迁移条件写在仓库里，避免依赖某次对话的上下文。

## 当前阶段：P1，可重复的竖切片

目标是让一局 3–5 天的流程可以反复试玩，并且每个环节都能解释玩家的决策结果：

1. 白天在 36×24 的同一张地图上探索、采集和发现地标。
2. 靠近幸存者，请求支援、下达岗位命令，触发关系和需求驱动的事件。
3. 使用资源完成建筑、防线、农务和广播中继链。
4. 在原地图上进入夜间尸潮，保留玩家、NPC、防线和僵尸的连续位置关系。
5. 弹出每日总结，结算伤亡、资源、关系和任务，再进入下一天。
6. 关闭、恢复、重置存档都不会破坏旧档；事件命令和存档快照可以审计。

状态终端负责资源、任务/事件、幸存者、地图、中继、日志和背包等非基本状态；地图上只保留生命、行动体力和即时危险这组基本信息。

### P1 当前远征—营地循环

食物是共享营地库存中的即时应急资源。行动体力归零后仍可立即进食，进食同时消耗营地口粮；体力不再因为归零而被锁到清晨。这样，玩家可以在危险地点做一次救急决策，但不能把食物当成无限探索许可。

远离营地的采集、地标探索和外围巡查会提高持久的“外围压力”。压力随外围时间继续升高，达到阈值后会在玩家附近生成有限的漫游僵尸；击杀只清出一个短暂窗口，压力不下降就会在后续时间补回，废墟高压时还会出现快速感染者或装甲僵尸。生成受全局上限约束，避免把规则变成实体堆积。

营地是主动整备中心，而不是体力惩罚墙：shelter 可恢复少量生命与体力并让压力下降，指挥所简报、仓库盘点和居住区集体晚餐分别降低压力或改善队伍状态；NPC 支援与在线中继进一步降低外围增长、提供夜潮防线和预警优势。外围压力、当前区域、支援人数和中继状态只在快捷键打开的状态终端中显示。

### P1 当前心理状态链：SAN、压力与士气分层

SAN 是个体长期的心理承受度，玩家和每名 NPC 都独立拥有 0–100 的 SAN。`stress` 继续表示短期负荷，`morale` 继续表示营地集体信心，三者保持不同职责：短期压力会磨损 SAN，集体生活与可靠支援会帮助恢复，低 SAN 会反过来影响感知、岗位脉冲、战斗撤退判断和个人事件触发。

玩家 SAN 会受到外围暴露、地标探索、近身反咬、尸潮开始和营地突破影响；shelter、医务室、指挥所、居住区晚餐、成功守住尸潮和回营整备提供恢复。SAN 低于阶段阈值时，玩家仍可继续行动，但会更容易触发心理危机事件，玩家可以选择回营静坐或承担更高的后续威胁。

NPC SAN 会受到岗位压力、夜战伤害、目睹同伴阵亡、孤立和营地安全感影响；同伴支持、轮班、晚餐、兵营训练和安全岗位提供恢复。低 SAN NPC 会降低感知和工作稳定度，更容易触发个人事件、请求支援或在夜战中撤退。所有 SAN 变化通过统一的状态变更器写入事件账本，并随存档保存。

SAN 数值、阶段、最近变化原因和全体 NPC 心智排序都放在状态终端的“心智 / SAN”标签中；角色标签只显示紧凑的 `SAN 数值 · 阶段`，地图 HUD 保持生命、行动体力和即时危险三项基本状态。

## P2：内容和因果

竖切片稳定后再增加事件分支、继任岗位、势力评价、僵尸类型和天灾。新增内容必须通过既有事件 schema、命令总线和存档迁移进入，不能另起一套临时状态。

## P3：表现层

最后统一正式像素素材、序列帧动画、音效、粒子和资源加载。表现层应依赖稳定的 GameState、纯 reducer 和 renderer adapter，这样 Web 与引擎可以共享规则。

## 引擎迁移闸门

满足下列类别中的至少两类，并且 P1 已冻结后再迁移：

- 中端手机优化后仍持续低于 30 FPS，或 P95 帧时间超过 33 ms。
- 活动实体达到约 50–100 个，地图扩大到约 100×100，需要真正的寻路、遮挡和碰撞。
- 需要大量序列帧、粒子、音频、资源热加载和可视化编辑器。
- 目标变成微信小游戏原生打包、离线运行、多端输入，或联网多人权威模拟。
- 事件命令、回放边界和 SAVE_VERSION 已冻结，并有 5 天试玩与存档迁移夹具。

当前判断：继续使用 Web/Canvas 完成 P1；若最终目标是微信小游戏，优先评估 Cocos Creator，纯 Web 则先保留现有实现或比较 Phaser/Pixi。

## 长期计划复盘与迭代入口

当前路线的优先级是正确的：先让“准备—尸潮—总结”循环稳定，再增加内容因果，最后打磨表现层，只有在性能、规模或发布目标达到迁移门槛时才更换引擎。线上 Sites 版本与 GitHub 镜像存在分叉，因此每轮都以线上 Sites 源提交为唯一可写基线，GitHub 只用于只读对照；版本对账和可恢复存档是所有内容工作的前置条件。

接下来的长期阶段固定为：

1. **P1.1 稳定与可回归**：完成浏览器 smoke、昼夜输入隔离、隐藏页面暂停/恢复、旧档迁移、地图占位和夜战坐标的自动化或半自动化验收。没有这组证据，不扩大系统边界。
2. **P1.2 内容因果**：以现有广播中继链为第一条可审计主线，补齐事件账本、NPC 个人链、营地能力、势力评价和尸潮预警之间的因果解释。新增故事必须走剧本设计师评审，不直接向单文件添加临时变量。
3. **P2 规则模块化**：把 GameState、命令总线/reducer、事件账本、任务推进、NPC 需求与存档迁移拆成可独立检查的 GameCore 边界；Web/Canvas 继续作为当前渲染适配器。
4. **P3 表现与素材**：在规则接口冻结后再统一像素素材、序列帧、音效、粒子、加载和移动端布局，素材变更不得改变碰撞锚点或事件语义。
5. **引擎评估**：只有当性能、实体规模、编辑器/素材需求、原生发布/多人需求、规则冻结这五类中至少两类同时满足，且 P1 有完整存档夹具时，才比较 Cocos/Phaser/Pixi 并做小型迁移验证。

历史阶段已以广播中继链三日竖切片完成样板验证；v80 设计冻结与状态边界已落地，v81 计划会 runtime 已接入，v82 已完成 SAVE21/CONTENT3、NPC 属性默认值、英雄晋升入口、岗位替代投影和五日 NPC 回放夹具；v83 前置切片已完成据点守军人口账本、每日 upkeep 和死亡释放回放夹具。

## v86–v90 长期扩展

v85 完成后，路线进入“游戏系统 + AI/Agent 基础设施 + 科研实验”双主线。详细出口见 `docs/long-term-plan.md`，记忆和实验规则见 `docs/project-memory.md` 与 `docs/experiments/README.md`。

- **v86 GameCore：** 从单文件渲染入口抽离 GameState、CommandBus、reducer、事件账本、内容注册表和回放运行器；先保持 Web/Canvas，不同时迁移引擎。
- **v87 RolePlanner：** 计划会先接一个可替换规划器，再接母巢首脑；LLM 只输出受 Gate 校验的 `Intent`，规则 AI 是无模型 fallback。
- **v88 Evaluation Lab：** headless 多 seed 运行、事件链覆盖、节奏和成本指标、JSON/CSV/Markdown 报告。
- **v89 Design Optimization：** 在 held-out seed 和人工剧情评审保护下搜索数值、冷却、波次、事件权重和有限 prompt 变体。
- **v90 Open Source：** 抽出 `event-chain-core`、`role-agent-runtime` 和 `gameplay-eval-lab`，同时保留尸潮农场作为完整示例。

Colab T4 只作为可恢复的批量实验 worker；稳定线上服务、常驻 API 和玩家连接使用受控 VM 或其他托管运行时。所有远程任务必须有 manifest、checkpoint、run idempotency 和可下载结果。

## v80–v85 整体路线（尸潮农场）

正式副本基准为 day14，最终尸潮窗口为 day12–16。P1 竖切片和 SAN 基础保持不变，后续内容按以下顺序扩展：v80 设计冻结与状态边界（完成）；v81 营地自治、计划会、commandPoints 和 `campCollapse`（完成首个 runtime 竖切片）；v82 NPC 属性、英雄晋升和岗位替代；v83 科技、建筑、据点和支线；v84 最终尸潮、多结局和二周目直达；v85 动态 UI、像素资源、性能和交接验收。

新增内容必须经 `剧本/尸潮农场/01–09` 设计源、`11–16` 接口模板和 `docs/scripts` 剧本卡三层映射；固定人口、`resonancePressure`、存档迁移、回放哈希、夜间保护和实体上限是所有阶段的共同验收项。当前 UI 卡片仍有硬编码，动态渲染属于 v85，不把注册表存在误认为功能已完成。
