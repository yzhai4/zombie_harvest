# 尸潮农场整体迭代计划

**版本基线：** `zfarm-world-1.0` / `SAVE_VERSION=20` / `CONTENT_SCHEMA_VERSION=2`  
**目标窗口：** day 1–16，day 14 为最终尸潮基准  
**适用范围：** Web/Canvas 规则验证平台；不在本计划中迁移引擎或引入多人持久化。

## 当前基线与缺口

仓库已经具备昼夜循环、广播中继样板链、SAN、事件契约、事件账本、回放、内容注册表、事务效果和保存迁移。`WEAPON_DEFS`、`EVENT_CHAIN_DEFS`、`NPC_STORY_DEFS`、`TECH_NODE_DEFS`、`BUILDING_DEFS`、`FACTION_DEFS`、`OUTPOST_DEFS`、`NPC_ROLE_DEFS` 与 11–16 模板是基础设施。

v81 已接入 `campCollapse` 的配给/夜战账本、commandPoints 权限刷新、计划会候选/英雄投票/玩家提交/自治执行、计划会 UI、存档迁移与回放投影。仍需开发：14 天时钟与最终尸潮结算、`resonancePressure` 的完整内容链、十名 NPC 属性/英雄晋升/岗位替代、科技建筑据点和支线注册、动态 UI 卡片、近景/远景实体预算验收。当前 UI 仍有硬编码卡片，不能把扩展接口误认为完整自治系统。

## 统一设计输入

世界观和六视角法则见 `剧本/尸潮农场/01_整体世界观与叙事法则.md`；时钟与结局见 02；主线见 03；支线见 04；势力与敌人见 05；NPC 见 06；计划会见 07；战斗、科技、建筑见 08；预算见 09。11–16 是实现契约和模板，`docs/scripts/relay-chain-001.md` 是已评审主线样板。

## 版本计划

### v80：设计统一与状态边界

冻结稳定 ID、14 天窗口、结局阈值、六视角账本、效果 reducer、人口守恒和内容版本。建立剧本定义到运行时注册表的映射；不新增大规模 UI/引擎。

### v81：营地自治与计划会

实现 `campCollapse`、每日计划会、英雄投票和 commandPoints 权限阶梯。计划只在白天队列执行，夜间拒绝白天命令；写入账本并保证固定种子回放一致。

### v82：NPC 属性、英雄晋升与岗位替代

补齐生命、SAN、生产、武器/护甲/防御塔、建造、医疗、科研、后勤、指挥属性。落地十名 NPC 剧情卡，处理死亡、失踪、重伤、拒绝合作和最低功能替代；英雄价值必须在投票、战斗或生产中可观察。

### v83：科技、建筑、据点和支线

接入岗亭、水车、医院、检查站、南侧聚落门和首批支线。蓝图、维护、守军和补给距离全部从现有人口与资源结算；新增内容只注册定义、节点、文本和资源。

### v84：最终尸潮与多结局

把旧危机窗口替换为 day12–16；强度读取时钟、共鸣、崩溃、英雄、据点和科技。验收稳定守住、重创守住、空壳存续、营地崩溃和二周目直达路线。

### v85：表现层与开发验收

动态生成武器、建筑、事件和 NPC 卡片；接入像素资源、动画、音效和占位回退。完成浏览器 smoke、夜间保护、回放、旧档迁移、性能和交接验收。

## 设计/开发协作门禁

每个内容先有剧本卡、状态契约和六视角账本，再进入注册表。设计未通过时，开发不得加临时全局变量；若现有 schema 无法承载，先提交 schema 变更议题。效果必须幂等、可回滚、可记录；显示名称可改，稳定 ID 不可复用。

## 完成定义

v85 完成需同时满足：内容校验、夜间保护、三日 smoke、回放 self-test、旧档迁移、四类尸潮结局、人口不足和 NPC 死亡降级、动态卡片和实体预算记录均通过。所有限制与回滚点记录在 `docs/handoff/尸潮农场-开发交接包.md`。

## 权威文件与历史草案

`01–09` 是当前 `zfarm-world-1.0` 的唯一设计规则真相；`11–16` 是接口/模板；`docs/scripts` 是实现映射。目录中的 `02_十四日节点与事件账本.md`、`03_循环状态机与玩家自治规则.md` 仅作历史草案，不能作为新内容的触发日、权限或结局来源。运行时注册状态以 `dist/index.html` 和本交接包的“已接线/设计预留”标注为准。

## 参考证据与数字来源

外部游戏机制的核验记录在 `docs/design-reference-evidence.md`。Kenshi/WorldBox/Norland 支持自治与远景账本，Kingdom Two Crowns/Thronefall/Ratropolis 支持昼夜准备—波次节奏，Stardew Valley/动物迷城支持直接战斗与关系路线，CK3/RimWorld 支持性格/事件导演的可解释决策。14 天、阈值、commandPoints、实体预算和单武器上限均是本项目假设，不是外部作品官方数值；Tower Train 和“紫色晶石”只采用已核验的高层信息或标为待核验。

## 本轮最终决策

本轮以用户确认的 **14 天主窗口、day12–16 正常结算窗** 作为开发基准，覆盖此前讨论中的其他候选时长；若 v81–v85 平衡测试需要改动，必须走 contentVersion 变更和回放迁移，不得在实现中私自改日程。
