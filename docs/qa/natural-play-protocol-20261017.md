# 自然混合试玩协议与当前节奏缺口（2026-10-17）

**状态：只读设计审查与 proposed 验收协议；尚未执行自然三日。** 本文没有修改 HTML、runner、游戏规则或活动浏览器。审查基线为开发 HTML SHA-256 `51faa0c7c62607aa0d4e280a5bc056e4eb01b374b1ae3f45782c232445ae1662`，SAVE21 / CONTENT3。当前 C 使用归档 v2 runner `bc16789fb58d60ea141488c8a5bd393a98e7de673bbf21efcddf123418db93ff`；它仍属于训练主导的公开行动日历回归，本文不操作 C，也不预判它的结果。

## 1. 目的与证据分层

自然混合试玩要观察“资源与体力约束下，准备营地、认识 NPC、探索、遭遇敌人、承担事件后果，再依据后果调整行动”的真实循环。它不要求玩家把每个系统都刷满，不把训练、巡检、晚餐或反复开面板当作消磨日历的工具。

分开保留三类结果：

1. **calendar regression：** 现有 runner 的连续日历、配给/计划/保存检查；重复训练会提高 SAN、士气并降低守卫压力，不能证明自然节奏或平衡。
2. **fresh natural mixed play：** 新档从第 1 天 06:00 连续玩到第 4 天至少 06:00，保留实际行动动机、后果和失败；只能在真实到达后声称连续三日。
3. **crisis branch probe：** 同一断粮基线的选择对照；若使用完整真实 writer 存档在 boot 前分叉，它是“自然来源存档的受控浏览器夹具”，不能并入无注入的新档自然三日。

本文是协议，不能替代任何一类的终态报告、原始保存或浏览器证据。

## 3. 执行前固定的合同

- 独立新 profile、新输出目录，同一冻结 HTML 的真实 main-document response SHA；记录 seed、SAVE/CONTENT、runner/手工协议版本和参数。保持当前默认时钟 rate=1，不注入保存、资源、NPC、敌人或模型输出，不调用隐藏游戏函数。
- 行动依据来自真实可见地图、HUD、人物/事件/计划面板。只读保存用于独立核对事实，不让策略利用 UI 尚未披露的远处敌人、隐藏地标奖励或 NPC 私有知识。安全层能否获得这些信息要单列，不能冒称完整 actor projection 已完成。
- 每次劳动前观察玩家 HP/energy、可见活敌及其接近风险；能逃离就先逃离，资源允许再治疗/进食，只有胜算和体力足够才近战。不能假定营地、兵营、NPC 或塔必然保护玩家。
- 兵营训练最多每天一次、三日合计两次；NPC 的训练事件也计入总次数。只有实际训练需要、守卫压力或 SAN 风险才选择，不为凑分钟训练。晚餐最多每天一次，实际恢复/用餐有动机；巡检同一岗位每天最多一次，不循环刷士气。
- 采集只取尚有 amount 的真实节点，建设只处理具体防线/生产需要，维修只修受损同一实体，进食须有实际恢复需求。不得以无效点击、空支付或同一增益按钮重复来填充时间。
- 预先记录真实操作、读面板思考和无操作等待时长。自动化不连续空等超过 120 秒，也不以无目的来回走动替代等待；累计空等超过 6 分钟，或可达有意义行动已耗尽，就终止该轮并记录节奏缺口。这些是本协议的评测预算，不是新增游戏规则；人工游玩真实的阅读/思考时间另列，不能事后把自动化空等重命名为思考。

## 5. 当前构建的可达性限制与退出条件

第 1 天 06:00 到第 4 天 06:00 是 4320 游戏分钟。只依靠当前前台 timer 的理想下限约为 **86.4 分钟真实时间**；劳动会减少部分等待，但加载、报告、存档观察和隐藏页面又会增加真实耗时。该换算不是性能实测，也不是三日完成预计时间。

当前有限行动、少量训练上限与没有公开休息推进，不能保证在 600 或 2400 秒内自然到达三日终点。不能为了把结果变绿而循环采无需求材料、重复建无用途建筑、反复训练/巡检，或者等待几十分钟后声称节奏合理。先按本协议执行有意义的混合切片；达到空等/无目标预算则记录 **INCOMPLETE_PACING**，停在实际日期。它既不是自然三日通过，也不自动证明存档或战斗有 bug。

分别报告：

- **PASS_3D_OBSERVED：** 实际连续到 day4≥06:00、同构建/零注入、所列最小覆盖完成、保存/日历/人口与资源账本可解释。它仍只是一个种子与一条策略的可靠性证据，不是平衡结论。
- **GAMEPLAY_LOSS：** 玩家死亡或真实营地灭亡。分开记录 playerHP、核心建筑耐久、活动人口与 campCollapse，不把玩家 hp 字段称为 campHP。NPC 个别伤亡可以是有效玩法后果，不能抹除，也不能称零伤亡通过。
- **RULE_OR_UI_FAILURE：** 公开按钮/合法移动失效、夜间白天命令漏过、重复支付/奖励、同实体状态错误、存档破坏/加载改变人口等，有具体前后证据。
- **INCOMPLETE_PACING / NOT_TRIGGERED / NOT_COVERED：** 分别用于节奏预算不足、危机未自然触发、某系统没有实际覆盖；三者都不能改写为通过。

## 6. 断粮三策略：与主自然路线分开

断粮只在 `onDayStart` 且 `food_days<=1` 等条件满足时开启，十名活跃 NPC 当前日需为3；主自然路线正常补给后可能三日内根本不出现。不得为了制造事件而空吃、循环晚餐、故意浪费资源或伪造缺岗。三日没触发记 NOT_TRIGGERED，可另开后续多日观察。

比较使用三份独立 fresh run，固定同一构建/seed、相同危机前规则策略与训练上限；首次实际出现断粮时记录完整基线。若它们的实际危机日、食物、HP/energy、可达食物节点、后勤资格、敌人态势不一致，只作描述比较，不能声称严格因果。需要同状态对照时，另用同一真实 writer 的 boot 前分叉夹具，明确从自然三日证据中剥离。

| 策略 | 公开可达操作 | 核对内容与不能夸大的范围 |
| --- | --- | --- |
| A 立即留守 | 第一次打开该 episode 即选择 `ration / 留守警戒，接受缺口` | 食物不变、campCollapse 实际 +2（封顶记录实际差值）、不增加外围暴露；没有岗位占用、节粮或减饥饿效果。选择后结束该 episode。 |
| B 立即取粮 | 相同危机时选择 `forage / 取回后勤应急藏粮`，前提为健康可履职后勤在岗、整局 cache flag 未用 | 食物实际 +2、resonancePressure 实际 +2、永久 flag 和同 episode 完成；整局一次。当前是抽象效果，没有旅行、离岗时长或队伍实体，不记作玩家地图探索/采集。 |
| C 延后并先补粮 | 关闭/切换事件面板，使用真实可达的莓丛/成熟菜田等先补粮；前后记录劳动分钟、体力、暴露与敌人风险，再重开原事项观察 | 原 active episode 应仍保留，不因库存改善自动结算；当前 choice Gate 只复查阶段/选项要求，不重新执行开启时的 `food_days`，补粮后原选项可能仍可点。仅观察 pending，不伪称执行了内部 skip。 |

主要终点以“首次危机后第一个实际午夜/下一次配给”为共同 horizon，另列补粮是否先于午夜、食物总收入与支出、HP/energy、NPC 饥饿/压力/健康、campCollapse、resonancePressure、藏粮 flag、episode 身份及选择回执。资源不足或安全路线不可达也保留为 C 的实际代价，不能免费送到节点。

可加 D“暂不处理且不专门补粮”作描述对照，但它不是当前 UI 的 skip：没有显性跳过按钮，关闭面板不调用 `ifSkipped`；旧实例可跨日保留，day14 过期才通过 hook 执行 ledger-only。A 的额外 +2 压力而延期没有该结算，已是局部激励不对称；一次试玩只能证实可达性和事实，不能把它解释成平衡合理，也不临时给忽略强加惩罚。

## 8. 已接入开发：有边界的营地等候

上一版“休整至清晨”是候选方向，最终采用[营地等候ADR](../decisions/ADR-20261017-camp-rest-v1.md)的30／60分钟、实际庇护所1.25半径和200ms×1分钟步进。没有居住区等价入口、自动到清晨、额外治疗或资源奖励。N已明确标为发起遭遇，仍不跳日。

源码25d315ae／HTML32f911f6已按[本轮QA](camp-rest-20261017.md)验证小步真实模拟、危险／伤害／新事项中断、取消、午夜和保存刷新。真实Chrome六场93项通过；真实hidden尚未验成。既有整备奖励独立，普通等候只获得原时间后果；被动体力分片错误另有明确修复记录。

自然路线允许为具体目的等候，例如作物成熟或一次已有的恢复窗口。每次记录目标、预计／实际分钟、开始与结束状态、是否中断、后续公开行动与资源变化。连续无目标等候单列为空闲时间，不以重复等候填满day4后宣布自然循环成立。

下一轮先运行有预算的短混合路线：公开探索／采集→实际建设或农务→NPC事项或中继推进→按已知威胁自卫→有目标等候→结算／恢复。内容耗尽、资源不足、路径锁死或危险不能解时保留终态；不无限重试、删敌或补资源。路线可持续后再运行当前构建的新档三日，另报无操作占比、拒绝原因与有意义决策，而非只报日历。
