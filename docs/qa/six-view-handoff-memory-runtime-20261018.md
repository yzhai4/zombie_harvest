## 文本与时间含义

真实投影在当前源码8143—8150只输出三类：`交付记忆：未记录`、`交付记忆：暂不可核实`，或“交付记忆：第X天 HH:MM，玩家把广播核心交给了我。”日期由胶囊 `tick.world` 派生，不取当前phase／schedule时钟或当前会话时间。实际报告中的world380显示第1天06:20，即使来源的phase为0，也不会显示为00:00。当前文本没有“今天”“刚才”“正在等你”“将在某时完工”等随刷新失真的表述。

这是已经完成的一次交付，而非带截止时间的承诺：当前合同没有dueAt、履约窗口、未来行动义务或失约事件。不要为让记忆显得有用而在后续说明中追加这些含义。现有schedule／lastReport可表达当前安排，但不能反向改写这条本人历史。

已交付旧writer明确保留原业务与原handoffAt，包括旧原件合法的null；新槽适配为null。UI写“未记录”而非“未收到”，在语义上保留了不知道的空间。实质剩余风险是玩家可能把短标签误读成任务未完成；这是需要观察的理解问题，目前没有证据要求新增惩罚、重发核心或修改旧事实。

## 既有pilot可问的三个问题

1. 玩家看到“第1天06:20交给了我”后，能否区分“这人接收过核心”与“中继已经在线／这人现在仍负责施工”？分别让其指出记忆行与当前工程状态，不诱导答案。
2. 在原已交付旧档显示“未记录”时，玩家会否以为交付丢失、需要再找核心？保留其第一反应，再看现有主线／中继状态能否解除误解；不把提问当通过判据。
3. 改岗／继任情境下，玩家能否理解经历属于原接收者而不是头衔？同时确认其是否期待死者历史另有查询入口，把该期待记录为后续需求，而不声称当前已有此功能。
