**稳定 ID：** `npc-self-observation-v1`

## 玩家价值与规则来源

玩家靠近一个具体的人，第一次按 E 交谈时，应先听到这个人说明自身伤势与急迫的身体感受，再决定是否确认支援、另找食物或暂缓请求。现有首谈将生命、日程、需求、锁定目标和信任等机械摘要连在一起；本片把已有 hunger／fatigue／energy 读为有来源的第一人称线索，不增加帮助、治疗或合作承诺。状态查看卡仍提供原有信息。

依据 L0 [世界与叙事法则](../../剧本/尸潮农场/01_整体世界观与叙事法则.md)、[NPC 体系](../../剧本/尸潮农场/06_NPC英雄晋升与普通NPC体系.md)、[权限](../../剧本/尸潮农场/07_计划会与commandPoints.md)及[NPC 模板](../../剧本/尸潮农场/14_NPC剧情模板.md)：人口固定，伤势来自实际世界，陌生关系不授予指挥权，对白解释事实而不单独发奖。这里的个人 `relations.trustToPlayer` 不是营地 `campTrust`，也不改变计划会或英雄权限。

当前对照为 HTML `61ea64b27a65cc4a271c214c16126b40a453eae40c8684c106bc8edc89e5f115`。真实入口与业务合同见[NPC 公开动作 ADR](../decisions/ADR-20261017-npc-public-actions-v1.md)；更广的[ActorObservation ADR](../decisions/ADR-20261017-actor-observation-v1.md)仍有独立范围。本卡不是新 EventChainDef、奖励节点或包内 storylet，不新增注册链身份。

## 触发与路线

- 仅 DAY 中、原 `npcPublicActionGate` 已成功、同一 live NPC 尚未支援且本次操作为 `dialogue-open` 时触发。speaker 与 subject 都是原 Gate 返回的同一 NPC，不重新选择最近的人。
- 在成功原 Gate 后、写 `selectedNpc`／`npcTalkOpen` 等本次 UI 标志前，同步捕获自身事实。内部可用固定 `action:'view'` 的原纯资格检查，再显式重核距离≤1、固定roster与双向驻守；不可重跑默认 `interact` 推导操作或先打开确认，误将免费首谈变为付费支援。
- 查看仍是 1.25 格内的原纯查看；首谈仍按原 1 格执行范围。`critical`、E=0、暂停时钟的原免费首谈继续合法，伤势自述不代表可劳动、可战或接受了支援。
- 保守路线：听完后离开／不确认，不产生额外代价或期限惩罚。再次到访按当时真实情况首谈；没有永久“一次对白完成”奖励。
- 介入路线：按原公开确认请求支援；2E、真实 15 分钟、关系／SAN／bond、死亡中断与保存全部沿原合同。自述不提供成功保证。
- 自治路线：玩家不交谈时，NPC 按既有需求、岗位、伤势和感知继续行动。本片不主动弹台词，不暂停世界，不刷新感知或写新记忆。

## 可说的事实与固定文案

仅使用合法自身 `lifeState`、由真实 `hp/maxHp` 得到的原有四分刻度 `hpBand`，以及本人 `needs.hunger/fatigue/energy` 的有限分档。三个需求字段分别严格接受0…100的有限数字；缺失、字符串、NaN或越界各自为unknown，不补0，也不据一项坏值抹掉其它合法自身事实。合法且未触发急迫边界的分档名固定为`normal`。基础自述不含精确 HP／需求值、当前锁定目标、坐标、SAN、信任数字、他人情况或未来结果。capture／observation只绑定ID，不包含name；界面称呼取自同一成功Gate返回NPC的既有UI label，不从自由输入接受subject。

| 自身 lifeState | 基础句 |
| --- | --- |
| healthy | 我目前没有受伤。 |
| injured | 我受伤了。 |
| critical | 我伤得很重。 |

`dead` 不说首谈。未知或非法伤势不能补为健康；若可信捕获无法确认，使用不归于 NPC 事实的界面提示“暂时无法确认这位角色的伤势信息。”，不修复或重写世界字段。

自身伤势还须只读核对现有`syncNpcLifeState`规则：对hp>0者，hp<30应为critical，否则hp<maxHp应为injured，否则为healthy。若已保存lifeState与该规则冲突，即使旧validator和原publicGate允许继续，也统一使用上述unknown界面，不同时说“没有受伤”和“生命余量已经很少”。不调用sync函数、不改旧档、HP或lifeState；原免费首谈的命令／0E／0分钟仍保留。全局健康一致性和旧保存修复是另一个问题，不借本片悄悄迁移。

仅在披露后确有 `hpBand` 字段时，追加下表一句。四分刻度是现有 `round(clamp(hp/maxHp,0,1)*4)` 的粗略生命余量，不是精确百分比、体力、治疗预测或战斗能力。

| 已披露 hpBand | 追加句 |
| --- | --- |
| 0/4 | 我的生命余量已经很少。 |
| 1/4 | 我的生命余量大约还剩四分之一。 |
| 2/4 | 我的生命余量大约还剩一半。 |
| 3/4 | 我的生命余量大约还剩四分之三。 |
| 4/4 | 我的生命余量接近完整。 |

需求与hpBand采用同一披露门槛。只有已披露的需求分档可驱动以下固定句；按饥饿→疲劳→低精力的顺序最多追加一句。unknown不当作normal；一项unknown不妨碍表达另一项已知的触发感受，但不能据此说其它需求正常。

| 已披露需求分档 | 触发边界 | 固定句 |
| --- | --- | --- |
| hunger=urgent | hunger≥70 | 我饿得厉害，得找点吃的。 |
| fatigue=urgent | fatigue≥70，且无已知urgent饥饿句 | 我累得厉害，需要休息。 |
| energy=low | energy≤25，且无前两句 | 我快没力气了，需要缓一缓。 |
| 各项normal或unknown，无上述触发 | hunger／fatigue的合法值<70；energy的合法值>25；坏值unknown | 不追加需求句；不声称身体一切正常或可以履职。 |

合法低信任导致详情被遮蔽时追加“具体情况，我暂时不想多谈。”。这表示知道但不愿披露，不把已知自身伤势／需求写成unknown。关系字段缺失或非法时保守地不披露hpBand／需求分档，仅保留合法基础句；可另给中性界面提示“更多身体详情暂时无法确认。”，不虚构实际信任值或角色不信任的心理事实。该异常也不增加首谈支付或健康门槛。

例：苏禾：我受伤了。我的生命余量大约还剩一半。我饿得厉害，得找点吃的。其后另列原界面操作提示“再次按 E 或点击确认请求支援”，不把按钮操作说明写成角色接受了命令。不得追加“我能继续战斗”“我能保证治好你”“附近安全”等无本片来源的句子。感受只描述本人，不自动请求物品、吃饭、睡眠或改岗位。

首谈整句必须实际可读，不能只在DOM中存在而被单行省略号剪掉。专用`npc-self-dialogue`提示允许换行，宽度为max-content且最多min(90vw,520px)、圆角14px，保留12000ms；不加对话UI缓存或保存状态。任何普通后续toast清除专用class，恢复既有单行样式与1800ms；沿原generation超时保护，不让旧callback隐藏新会话提示。桌面与至少390px宽实际布局均须留图。可在首谈typed proof已实际保存后等2000ms观察同一句仍可见；期间真实ticks及当前状态变化单列，不能把稍后状态当作首谈当时事实。

## 实际信任与披露

知识先由同一 live NPC 的 self 授权获得，再与披露策略取交集。真实、有限且处于 -100…100 的 `npc.relations.trustToPlayer` 是唯一关系输入；alignment 与 playerProgress 没有本片批准来源，保持中性，不从营地变量或调用者输入补入。

沿现有 `observer-expression-v1` 的中性规则，score 为 `clamp(.5 + trustToPlayer/200,0,1)`；基础姓名／lifeState 已公开，`hpBand`与需求分档仅在实际trustToPlayer≥-10（等价score≥.45）时披露。因此默认个人trust=0仍披露，-10为包含边界，低于-10同时遮蔽刻度与需求。这不是新增声望阈值或要求玩家先刷好感。缺失、NaN或越界trust单列关系无效，不走“默认0贡献后score=.5”的路径；不伪造trust=0或-100。

固定文案只消费已披露facts，不能自行读取raw HP／needs或再放宽阈值。AI OFF／ON均使用同一授权、披露和固定文案；不接模型、网络请求、提示词或新能力。

## 六视角合理性

| 视角 | 因果与约束 |
| --- | --- |
| 玩家 | 同公开目标听到可读的伤势；首谈与确认分清，查看卡保留；不以对白代替实际支付或合作结果。 |
| NPC | 本人能说明自身伤势、饥饿／疲劳／精力感受，真实关系只减少详情；critical可自述；死亡／驻守／目标失效走原拒绝，不从身份岗继承他人知识，也不把感受当工作准入。 |
| 营地 | 无新人口、资源、治疗、劳动、CP 或奖励；原需求、配给、岗位和支援代价继续运行。 |
| 势力 | 不新增外交、秘密、声望或通讯；个人信任读取不触发营地信任与关系变更。 |
| 敌人 | 不报告隐藏目标、锁定 ID 或安全结论；不调用感知更新，不因说话停敌或删除威胁。 |
| 全局链 | 私有同步捕获和固定投影保持纯读；现有 npc.interact／dialogueOpened 命令事实、幂等和 writer 保持，不另造观察完成事件。 |

## 兼容、降级与幂等

无新 SAVE 域、无持久 observation、无 contacts TTL 变化、无新人物功绩。旧 writer 原事实与旧收据保留，不回填“过去说过什么”。reload 后 `npcTalkOpen` 沿原临时 UI 语义，下一次免费首谈使用当时事实，不带入旧 observation。

重复显式 commandId 沿原 CommandBus 在 reducer 前回读；不重新捕获、不重复开确认、不改记忆。普通再次首谈是原动作，不发收益。成功首谈本就会改变 UI 标志、写原命令／dialogueOpened 和走既有保存路径；只有 capture／project／固定文案函数必须零业务写入，不能把整个命令或既有 renderer 宣称为零写。

死亡、离营、失踪或不在原 Gate 允许的会话中，保留原拒绝理由；人数不足、缺岗、材料不足与建筑损坏不由对白修补。没有本片计时节点、过期处罚、冒险收益或 fallback 奖励；冒险仍是玩家随后选择的原支援／命令。

## 待验出口与回滚

- 真实 inline 首谈成功后，捕获早于 `npcTalkOpen` 写入；原同 NPC 首谈0E／0分钟、dialogueOpened与确认2E／15分钟分别成立，status inquiry／命令／中断无变更。
- healthy／injured／critical、E0、暂停时钟、trust0／-10／低于-10及缺失／NaN／越界关系分别核文案与披露；0/4活人不说成死亡，4/4不承诺无风险。需求69／70、25／26、三项同时触发优先级和各项缺失／坏值分别核；normal与unknown不编造“可履职”或“身体正常”。
- 未知／detached／重复ID／死亡／驻守／坏坐标、渲染后移动或删除目标不替换他人；capture不借修补或宽快照读取额外事实。
- 真实完整旧writer中合法但矛盾的healthy／hp1等状态：原loader／Gate／免费首谈仍可继续，自述统一unknown且保存原HP／lifeState不被修正；不能只用非法输入拒绝冒称覆盖。
- 组件前后完整 state、RNG、storage、registry、命令事件水位与 timers 不变，结果深冻结且无原可写引用；整个首谈按原命令合同单独比较。
- 完整旧 writer 的实际 loader／writer／reload不增字段、奖励、关系或知识；显式重复命令不再运行组件。原NPC及受影响回归保持。
- 源码冻结并独审通过后，再以 exact HTML／runner／输入 SHA 验真实 Chrome 公开 E／按钮、自述可见、查看卡保留、确认与刷新。fixture-browser、source-VM、自然路线分层，不借旧绿色或本设计关掉完整 ActorObservation。

本卡当前所有出口均待验，无新增测试或浏览器结果。回滚为恢复原免费首谈摘要与原表达调用点，不修改玩家已保存世界和旧收据。
