日期：2026-10-18。角色：独立剧本设计／实验设计复核。仅只读仓库、原报告和已有运行物；没有启动游戏、浏览器、源码测试或修改原报告。本文件是外部设计建议，不是新一轮验收结果。

## 结论

长期方向没有被当前实现取消：Scenario Studio、完整规则 NPC Planning、Memory/Social、特殊角色跨副本连续性、玩家实验、精确反事实及条件性 learned World Model 都仍列为开放目标。当前最有价值的下一步不是增加更多表达 API，而是让已有中继目标形成可理解、可干预的实际行为闭环。A 的公开死亡和有效岗位反例提供了两个不同的阻碍：前者要求先查清实际操作／危险／观察时延，后者要求修复中继使用有效岗位的语义。两者尚不能相互归因。

建议顺序为：**公开探索与撤退的可操作性及真实代价 → 中继唯一有效岗位与停工解释 → 同协议 A/B 的任务后果与续局验证**。第三片保留工程受控 pilot 身份；自然三日、真人体验和普遍平衡结论继续开放。

## 4. 接下来三个可验收切片（按依赖排序）

### 第一片：让公开探索／执行／撤退成为可靠且可读的动作

**玩家假设：** 玩家能分辨“看塔”和“回收核心”的承诺，并在公开危险中执行可理解的自卫／撤退，或明确知道为何被阻止。

先针对 A 已有前缀定位最小因果：哪个实际入口触发了 `landmark.discover`；F 后的方向键是否进入原移动 consumer；位置不变由何种真实规则或输入状态造成。此定位不预设必须改产品。若为方法错误，只另冻新方法；若为产品错误，只修被证实的 consumer。风险提示依已有公开信息，不新增隐藏全图侦察或保证安全。

**验收：** 同原失败保留；新方法明确每次不可逆动作的真实父命令／gross代价／世界时间，公开方向操作有可解释的移动或阻止结果，危险停止能在有限时间结束取证而非长时间留在活世界等待报告。当前公开HP、采样世界分钟、最新存档水位分别记录。只跑对应输入／移动／时间／保存的受影响合同；没有新 source 时不重复整44合同。允许合法失败，不要求放宽敌人来保证存活。

### 第二片：中继按唯一有效岗位使用实际人员，并解释停工

**玩家假设：** 岗位缺失真的造成相应工程阻碍，继任只恢复一个当前职责，玩家能理解缺什么及怎样合法恢复。

最小实现范围是现有 relay 的资格选择、去重及其实际筹料／工作 consumer；沿用已存在的唯一有效岗语义，保持人物身份、死亡、人口、旧贡献和历史，不新增通用调度框架。default 与现有 opt-in 两条消费路径都应列出受影响点，不能只改展示数组。正式职责／支援／伤病／离营的原准入保持，不能借修双岗改健康规则。

**验收：** 原 quartermaster→carpenter 反例从两个槽变为一个槽，quartermaster 空缺可见；真实已到该阶段的中继不会据此凭空推进、扣双份或发成功。合法补岗后才恢复相应进度，refresh 不重复结算；完整旧 writer 保留原世界事实。缺失／恢复来自实际机制或明确 TEST-ONLY boot 形状，不把直接函数审计称自然 C。只有这条完成后才把 C 当作有效的单因素岗位实验。

### 第三片：把核心交付到工程后果闭环，再完成工程 A/B 对照

**玩家假设：** 玩家通过公开阻碍能选择补给、介入或等待，并看到核心交付如何形成真实筹料、施工与预警；粮食压力是否改变其安排是待检问题。

复用现有发现→交付→筹料→施工→online→forecast，不先造新内容图或记忆框架。若现有任务摘要不能解释实际停工，只为这条 consumer 补最小事实来源和下一合法行动说明；这才是 EventFact／后续记忆的候选消费点。先接实际后果，再扩全套长期系统。

**验收：** A/B 同构建、同 seed、同策略优先级、同有限预算，各只执行预先声明的一轮；原 A 死亡原件仍保留，新版本须明确为何重做、差在哪里。分别记录回收／交付、真实材料与工程分钟、劳力、缺粮选择、危险干预、终止及 refresh 去重；未 online 就报未完成，预算删失与产品软锁分开。B 的因子写“初始有限食物可用量”，不能改称仅库存。C 在第二片合格后另开；D 留待单因素可解释。工程结果之后再安排小真人可理解性／继续游玩意愿观察，不以这两臂推断乐趣或普遍生存率。

三片没有删除长期目标，也不承诺在同一轮完成。Studio、完整规划、Memory/Social、连续性、全观察与自然三日各保留原出口；本次只是按已经暴露的实际依赖选下一步。

## 5. 工作流／Skill 的最小反馈建议（不在本任务修改）

1. **目标段落：** `docs/iteration-workflow.md` 的“日历回归与实际执行版本”动作安全条，以及 iteration Skill 的同名段。建议追加：**“读／选中操作若实际触发业务命令，按真实效果计为行动；主要动作数在终态以已接受／已支付或真实中断的父命令校对，预设 UI 标签不作为免费证明。实时 UI／权威采样与最新耐久 writer 分列世界水位和时间，不以存档字节未变推出实时状态未变。”** 影响：修正本次核心发现漏计与死亡保存混淆，不改既有原报告。陷阱：不能把所有自动 `world.advance` 子命令又算一次主要决策，或为了同步取证暂停游戏。
2. **目标段落：** 同一动作安全条／持久浏览器任务的失败取证段。建议追加：**“触发危险停止后，只执行预先限定的最小公开 UI／最新保存取证并尽快关闭；记录观察 RPC／截图耗时及未保存前缀。撤退输入无位移时先查焦点、碰撞和输入 consumer，再决定是方法修正还是产品修复，不凭一次采样放宽规则。”** 影响：把观察本身的活世界时间纳入风险，避免止损阶段继续暴露；不删死亡，不为绿反复重开。陷阱：没有 checkpoint 的终态必须诚实标未持久化，不能补造保存或把关闭当完成刷新。
3. **目标段落：** iteration Skill“选择迭代模式”的单因素条，以及 adoption plan 的 C／实验出口。建议追加：**“单因素条件须通过该任务实际 consumer 的可用性核验；人口／存在／有效岗位不能互代，同一实体不得凭原身份占多个岗位。若条件本身失真，暂停该条件的效果比较，先修最短真实消费点；其他已授权范围、原失败和完整长期目标仍保留。”** 影响：先挡住 C 的伪缺岗／伪继任，而非通过扩样本或增加断言掩盖。陷阱：这不要求先做完整 P2／全 ActorObservation，也不把受控死亡 VM 当自然缺岗。

上述是三个局部规则补充，不新增审批流程、通用实验框架或证据副本。继续复用同字节来源／原输入和按影响选择回归，最终冻结矩阵与实际浏览器授权范围照原工作流完成；产品缺陷、方法失败、未完成和不可用分别保留。
