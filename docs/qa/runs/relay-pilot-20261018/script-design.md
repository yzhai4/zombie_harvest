## 3. 同一公开决策规则与路线

不固定隐藏坐标，不保证同一行动序列。两臂都按以下优先级：**公开近敌／生命风险→撤离或有预算自卫；实际补给／体力需求→合法补给；否则推进公开中继当前阻碍。** 不为凑覆盖建无用途建筑、训练、巡检或开启遭遇；N不是跳日工具。

1. **先读再动。** 记录目标“推进广播中继”、公开显示的当前stage／阻碍、准备选择的行动及预期代价。取任务／HUD／context截图、初始完整writer；事实核验端不能把保存里的隐藏信息送回策略端。
2. **公开探索→核心。** 从地图、任务和当前可见地标选择探索，实际接近旧广播塔并用公开context发现。保留真实 `landmark.discover`、3E gross支付、20分钟子推进与 `special.itemRecovered`。找不到安全路径即停在实际位置，不使用保存坐标导航。
3. **核心→交付。** 读取公开“待交付”提示，实际找长官context，点带真实token的 `relayHandoff`。该路径是 `relay.coreHandoff`，成功到briefed；**当前实际交付0E／0 advance，不把NPC支援的2E／15分钟套进来。** 无合法按钮或被拒绝时，记录可见理由和提交结果。
4. **筹料／施工。** 读公开缺口与进度；只为实际需求采集／补给／防守，或到合法庇护所发起有目的的30／60分钟等候。原中继自治按实际资源来源筹木10／零件5／石4及施工，不在页面直接调用推进函数。当前“先保防线／先保中继”“公共／静默频道”不是可用Choice，不把设计卡承诺当按钮。
5. **每次关键阻碍重述。** 核心拿到后、交付后、首次暂停或首次资源选择时，各用公开信息写一句“现在因何等待／我能改变什么”，再作决定。若公开提示只能说“施工”但不给可操作解释，保留信息不足，不从保存补台词。B可选择实际出现的v2备用粮或真实食物来源，不改额度／flag；没有可见可行来源就记录压力，而非补粮。
6. **实际终止＋刷新。** 到online＋公开forecast，或命中安全／规则／预算停止条件即停止继续推进目标。结束前保留关键完整writer，公开刷新一次并等正常新保存，核核心、材料、工时、身份和上线未重付。刷新留在480秒内；截止尚未完成刷新则写该部分未覆盖，不延长成绿色。

不要求强行让三位工程NPC接受支援；那会增加独立干预。必要且可见理由充分时允许一次合法支援／订单，按主要动作和真实成本记账。低精力恢复可能被relay职责接管，不能把rest标签消失自动当成安排故障或缺岗。

## 4. 结果与最小证据

每臂独立保留HTML／runner／输入及loader结论SHA、实际main-document response SHA（含刷新）、原始报告与终态、错误和cleanup。目标选择只用公开界面；完整writer供独立validator与事后账本核对，不作隐藏目标／路线／时机 oracle。若另有privileged安全veto，必须单列来源与范围，不能称策略完全只用公开信息。

主要动作逐条记录：公开目标与可见阻碍、选择理由／预期后果、实际父command及结果、gross支付／真实产出、worldMinute前后、子advance与causation、公开结果和下一选择。材料、粮食、人口、NPC需求／健康／有效岗／routineIntent、工程分钟与forecast分开；不把玩家HP叫营地HP。把所有拒绝、duplicate、自动世界推进及读图／导航耗时分别统计。

终态使用具体描述：`ONLINE_OBSERVED`、`PROGRESS_OBSERVED_INCOMPLETE`、`BLOCKED_PUBLIC_INFORMATION`、`INTERRUPTED_RISK`、`BUDGET_EXHAUSTED`、`RULE_OR_UI_FAILURE`、`GAMEPLAY_LOSS`或`INPUT_REJECTED`；未触发事件、未覆盖刷新／战斗各另列。没到online必须写未完成与实际stage，不把“路径能调用”当中继完成。

A/B比较以两条实际路线并列：公开信息能否支持下一步、行动选择如何改变、阻碍是否可解释、是否保留可行后续。相同seed不保证不同操作分片后的RNG／敌人轨迹相同；不从一个种子、一个自动化操作者或不同截止时间推断食物配置的普遍因果收益、平衡或乐趣。不重开失败轮找成功，不把后来的新方法版本覆盖原失败。
