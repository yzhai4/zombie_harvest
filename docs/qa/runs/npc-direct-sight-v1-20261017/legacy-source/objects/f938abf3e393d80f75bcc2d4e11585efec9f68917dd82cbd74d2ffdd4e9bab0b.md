# 尸潮农场六视角评估矩阵

每个事件或系统变更按以下字段记录“通过 / 需修正 / 不适用”，并附一条证据。

| 视角 | 必查问题 | 证据示例 |
| --- | --- | --- |
| 玩家 | 选择、代价、反馈、恢复路径是否清楚？ | 浏览器 smoke、事件日志、截图 |
| NPC | 岗位、需求、关系、SAN、死亡/缺席引用是否合理？ | NPC 状态夹具、事件账本 |
| 营地 | 资源、人口、建筑、信任、崩溃度和 command points 是否守恒？ | reducer 断言、存档投影 |
| 势力 | 关系、据点、外交和敌对反制是否可解释？ | faction/outpost 状态、历史记录 |
| 敌人 | 预警、准备、防线、夜战和威胁压力是否受玩家影响？ | night guard、威胁结算日志 |
| 全局链 | 前置、推进、终止、降级、幂等和回放是否一致？ | event ledger、replay hash |

## 结论规则

- 任一视角为“不通过”，本轮不得进入发布闸门。
- “需修正”可以保留在 draft PR，但必须有负责人、文件和下一步验证。
- “通过”必须引用静态检查、夹具、回放或试玩证据，不能只写“已检查”。
