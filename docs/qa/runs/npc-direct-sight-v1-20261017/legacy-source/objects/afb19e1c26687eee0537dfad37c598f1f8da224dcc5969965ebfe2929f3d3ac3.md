# ADR：公开农务共享目标与真实结算

2026-10-17；状态：accepted并已完成列明开发验收；SAVE21／CONTENT3版本不变，农务事件新增兼容proof字段，新建建筑立即沿既有ID约定赋身份。

## 真实问题

[自然fresh04与独立反例](../problems/PROB-20261017-public-crop-target-mismatch.md)确认：公开context按连续半径1.25显示可播种，默认reducer按五个轴向点做建筑AABB查找，导致浮点边界与斜向位置均空成功。detached同ID对象还可能被扣种而真实田块不变；远处live对象可绕距离。这些是实际入口／执行资格不一致，不用全局坐标取整或放宽建筑占用边界修补。

## 目标与入口

统一纯目标解析，默认保留state.buildings中首个附近garden／greenhouse的现有公开顺序，使用当前公开连续距离≤1.25。显式ID必须精确解析到唯一live对象；显式未知、删除、歧义、错类型或超距不回退到其他田块。兼容原live object调用，detached对象不取得live能力。实际执行再次校验，渲染时有效不是支付时有效。

公开crop按钮携带田块ID；默认、快捷／E、显式目标及实际承诺农务的建筑入口均由相同命令路径处理。UI显示播种／成长／收获状态和真实支付，缺种／体力等不能启用无结果动作。若旧建筑按钮只查看状态，就准确描述；不得显示播种承诺却发inspect空成功。

新建菜田必须在构建成功时获得唯一稳定ID，沿既有bld／hashStable(type:x,y)约定并避开现有ID；不消耗额外RNG、不重写旧对象。目标解析／渲染不得为缺ID或重复ID的任意输入补造身份。同一局新建→立即种植不依赖刷新或loader修补。

## 规则与账本

- 会话必须接受白天输入；game-over、夜间、REPORT／LOSS／恢复／退出、暂停时钟、非法目标或必要结算前置失败明确ok:false。判断先于支付与work动作。沿既有CommandBus记拒绝，不新增成功、人物功绩或奖励。
- 保留原播种1种子／gross4行动体力，原收获3食物、greenhouse另1medicine／gross6体力；原20动作分钟经真实advance兑现，原时间倍率与模拟副作用分别说明，不重写为小步或日历跳转。
- 必须先预核已知的必要advance命令编号及会话／时钟条件，不能在这些可提前判断的失败后留下扣款。未知模拟内部异常不由本切片假称已获得全局事务回滚。
- 农务父command与crop.changed成功事件都显式归属player-1，不能依赖不同容器的默认actor；world.advance时钟事件仍可归属system，经真实causation关联玩家动作。成功payload记录同一buildingId、类型、operation、支付前后、动作刚完成时的同plot变化、真实时间／advance的commandId、eventId与causation；自然恢复、NPC用餐、午夜成长等后果与gross操作截面分开。
- 同commandId沿现有总线识别重复，不二次扣种／收获／推进；拒绝命令后重复返回的duplicate不是后来成功。旧empty crop.changed保留，不追溯补成功事实、人物来源或奖励。旧保存不重seed／重算资源。

## 六视角

| 视角 | 合理性 |
| --- | --- |
| 玩家 | 能执行已经启用的近身农务；明确为何拒绝，选择的田块不会偷偷换成另一块 |
| NPC | 不凭旧空成功补功绩或记忆，不新增代替玩家劳动的人员或岗位 |
| 营地 | 种子、行动体力、食物、药草与时间保持既有来源和消耗；收获同田只能付一次 |
| 势力 | 不新增援助、信任或外交变化 |
| 敌人 | 保留原20分钟中的真实运动／战斗后果，不删敌、减伤或保证NPC救援 |
| 全局链 | 单一命令／账本／保存路径，旧历史不改，拒绝与重复不触发新成功 |
