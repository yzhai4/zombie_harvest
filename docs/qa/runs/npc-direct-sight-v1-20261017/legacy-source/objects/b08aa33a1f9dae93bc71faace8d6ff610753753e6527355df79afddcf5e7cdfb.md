本次只提出设计和测试契约，不把票源字段修正等同于完整自治、真实晋升试玩或饥荒平衡已经完成。

## 身份与可用性契约

以下是身份单一真相和可用性边界，数值与伤病按后面的D1–D8建议实施：

1. **身份单一真相：** 投票读取经现有 normalizer 处理后的 `npc.hero`。正式英雄使用已确认的 tier/status，不能凭 `progress=100`、eligible、`NPC_STORY_DEFS.promotedTier`、技能名称或 stale `npc.promotedTier` 获得正式票。
2. **初始身份：** commander、radio、doctor 的初始 promoted 状态来自既有角色定义和初始化；不要求补造一次晋升事件才能参加会议。
3. **普通与 eligible：** 可提供需求/岗位建议，但正式英雄票尚未产生。身份可用后只改变票源，不自动授予额外 commandPoints、主持权、军队或资源。
4. **死亡：** dead 角色不得成为新会议票源或执行岗位；无复活、补人或以代理人的 ID 复制死者权重。保存恢复不能把死亡英雄重新纳入。
5. **critical / injured：** 当前实现均减半；本卡建议injured保留本来票权，critical为0。实际syncNpcLifeState在HP<30时critical，其余未满HP为injured；HP99不应仅凭小伤失去一半表达能力。工作能力独立判断，不由票权决定。
6. **失踪 / 离营：** 是设计要求，当前缺少完整正式状态。下一轮若接入，应先声明观察字段、保存默认值、人口/岗位映射和解除条件；不临时给对象加 boolean 后声称完整实现。
7. **拒绝：** 现有 `npc.orderRefused` 是一次高风险命令拒绝，不等于长期拒绝营地合作。不能以 `lastReport` 文本、任意旧拒绝事件或个人 trust 高低，永久剥夺全部投票权。全局/提案相关拒绝的作用范围、期限与恢复方式须先定契约。
8. **暂代岗位 / 据点：** `actingRole` 或 `garrisonedOutpostId` 不自行改变英雄身份；主持、票权及远端参与需分别定义。不能将守军在 campLocal 中缺席直接等同于死亡，也不能复制原岗位 NPC 的票。

异常的 tier/status 组合和旧档恢复须在 normalizer 契约中处理；直接判定 raw 对象不是保存兼容验收。新票源辅助函数不负责晋升，不产生 `npc.promotion.completed` 或任何奖励。

## 同日候选冻结与晋升生效时点

按D6/D7建议采用以下快照方案；依据“同一seed/day/contentVersion/ledger snapshot”、每日一个实例和历史可审计要求，不宣称当前已经实现：

- `camp-plan-meeting-001:d<day>` 首次真实生成时投影当时的合法身份、可用状态、食物、危机和岗位建议，保存 candidates/ballots。同实例的 reload、普通重复 SUMMARY、额外同日遭遇不得重抽候选或抹除已提交决定；调试 force 不能混入正常玩家路径。
- **晋升在生成之前完成：** 新会议可读到真实 promoted 状态，按最终票权政策参与。
- **晋升在生成之后完成：** 获得身份资格，但不逆改该会议历史票；首次后续合法新实例投票时生效。不是在同日 force 重生会议来兑现票权。
- **身份失效：** 死亡/失踪/重伤/明确会议拒绝立即改变有效票并禁止相关岗位；原ballot不改。未提交时在原候选中按有效票、原basePriority、稳定ID排序，跳过不可行方案。已提交时保留选择和CP消费，按方案已声明的现有替代角色降级；无替代则安全等待/封闭高风险岗位，不静默换一套补给奖励。
- **已经 committed / resolved：** 不得通过晋升、刷新或再打一场遭遇清空 playerAction/history，再收一次 CP 或重发效果。安全重新规划必须有独立、已批准的因果事件与幂等键。

冻结候选不等于冻结角色生命和需求。新会议也必须继续从现有固定 roster 与实时可用事实生成，不沿用一个可以造人的“选民列表副本”。

读取有效票的纯projection不产事件；真实资格变化的reducer记录instanceId/npcId/reasonEventId/oldWeight/newWeight，同原因幂等。render或reload不能生成新的invalidation。全零票/无主持时用可观察的保守职责fallback，仍检查人口、工时和材料；livingRoster<3走营地存在Gate，不能造英雄或免费清collapse。

## 真实日历时序裁定

按当前日历修复的事实建议：第D天遭遇结算SUMMARY首次创建 `camp-plan-meeting-001:dD`，只记录不执行。关闭报告回到第D天剩余DAY，trust≥60且CP≥1的玩家最多干预一次；真实日界D→D+1进入DAY后执行一次。关闭可选报告不提前执行或刷新点数。

新日顺序为原计划资格/人口/岗位/材料预检→统一事务执行或安全降级→结算旧实例→按新日trust区间刷新CP。不能把新日CP送回旧会议再收干预费。现有day13末会议窗口本卡保留；day12–16最终准备锁定和晚期议程在v84另行裁定。

```text
SUMMARY D -> 首次候选/主持/原ballots
DAY D余下时间 -> 旁听或一次干预
资格变化 -> 原票不变/有效资格与执行Gate更新
真实DAY D+1 -> 执行或fallback一次/历史一次/新日CP一次
```

旧卡“次日干预后当日执行”和07“次日白天执行/当日岗位队列”存在歧义，需按本节同时修订。第一切片不在报告恢复主题中悄悄切换执行时刻。

## 断粮投影、真实排序与机会成本

`foodSituation` 的四个现有状态为“充裕、稳定、紧张、断粮”，来源是实际 food/dailyNeed；dailyNeed 来自实际活动人口。投影必须复用该来源，不另写一套模拟库存，也不把 NPC 个体饥饿等同于营地 food=0。

当前低粮修正给harvest或 `plan-medical-rotation-001` 加9；D8建议采集保留+9，医疗需真实伤员。将不可达“短缺”接到真实“断粮”只能修复信号，**不能证明采集胜出或进入前三**：score≥30后转支持票，多个候选已全部达门槛，最后仍由basePriority/ID打破同票。

本次只读执行实际planCandidateScore，显式输入四个当前硬编码投票角色、3/2/1/1权重、trustToCommander=0、collapse=0、resonance=25和默认autonomyWeights：紧张时六候选全7票，外围补采按basePriority排第6；断粮时补采降到0票，仍第6。此观察没有运行整局loader/晋升或browser，不是完整验收；D2/D3改变票源后还须重新观察真实排名。

断粮优先的目标是让营地合理比较保命供给、防线与医疗。核心即时失守时守门优先；有伤员时医疗有真实价值，无伤员且缺粮不无条件医疗加分。完整计划会的第二切片应采用明确的危机议程政策：ratio<1且存在真实来源、劳动和可控路线的供给候选时，前三至少保留一个，替换最低位非紧急发展议题；food=0且无即时核心失守危险时优先可行供给。危险必须来自实际威胁/防线事实，不能仅由防御basePriority常年压过断粮。

拒绝高风险补采后，可换真实农田收获、既有库存交易或配给降级。没有合法消费者/来源则记录“无可行供给”和欠账代价，不保底发粮；该议程政策尚未接线，需单独登记策略版本和危机/来源Gate。D8第一切片通过不等于此政策或真实饥荒自治通过。+9、阈值30和basePriority先作观察基准，后续多seed校准，不能只围绕一例调到必过。

候选卡须分别显示食物危机、支持理由、可行来源、岗位/路线风险与预期收益。评分或投票只是决策信息，不能直接生成粮食、药品、现有人口以外的采集队或免除夜战。

## 六视角合理性账本
