## 建议

不要先造通用Planner接口。现有FSM已经有需求漂移、自主取粮、日程移动、工作脉冲、感知、支援与中继施工。最值得做的小闭环是：**一个有效木匠根据本人精力真正取消例行工作，去既有居住区休整，再返岗，并让玩家看懂原因及接管办法。**必须改变真实移动目标和工作资格，不能只新增trace或台词。

首片范围限唯一有效木匠、DAY、本地、身份／坐标／需求合法、未支援且无中继任务占用的例行工作。先以健康木匠做pilot；不修改critical既有支援／作战政策，不把所有NPC统一停工。无新资源、免费恢复、功绩、关系奖励或LLM。

## 原基线的具体反例：源码推导，本次未执行

DAY09:00，本地ready有效木匠、未支援，无威胁／中继任务，其他需求与SAN正常；energy23.5、simMoveClock15、workClock59。一次真实advance(1)按现源码可走：

1. `resting`因energy<24为真，energy加.045；5077先显示“休整 · 精力恢复”。
2. 5086的目的地只看钟表schedule；09:01仍指向workZone，而非休整地点。
3. behavior的rest门是energy<20；work blocker是energy<22，均未触发。
4. routine末尾pulse到60，5034–5038写回岗位工作与completed，同一步既恢复又“完成工作”。

另外fatigue>88而energy较高时，behavior可为rest，但生理resting不看fatigue，疲劳仍增加；blocked之前还会先设工位目标。这是实际多writer冲突的线索，不是已运行反例。未来应先用真实source固定这一旧版结果，不增加虚拟Planner来制造问题。

## 最小行动合同与接线

- 候选仅`routine-work`和`recover-energy`。输入只用本人实际精力、唯一有效岗位、作者已有home/work区域、当前真实职责占用；不读取隐藏敌人全图位置／未来伤害／他人私有需求，也不做全图找床或rollout。
- 开始恢复沿已有`energy<24`；结束可采用5077已有文案边界`36`，但这是**待冻结的迟滞假设**，不是声称当前已生效。恢复开始后取消本片例行工作，motionTarget改homeZone对应CAMP_AREA；结束后回work区重新积累工作时段。缺合法目的地则停留并解释，不造床位、不瞬移。
- 恢复期不发例行completed，不保存休整工时credit，返岗后不得爆发4次“补做”。保留此前真实完成历史。恢复只沿既有每分钟energy+.045、fatigue−.028和SAN规则，不flat加值。把恢复延续到36是行为改动；23.5→36无其他影响约278游戏分钟，可能占掉上午，必须作为成本评估，不能偷偷加速。
- 保持正式职责优先：原支援／合法命令、relay briefed/staging/building占用、夜战、离营、死亡和阶段变化使本片让权／取消，不撤销原职责。原alert/guard-alert/combat/patrol/cover由原感知作战拥有，新分支不覆盖其target/behavior。解释只说“让出现有职责”，不从旧contacts编造“刚看见敌人”。
- 决策接在既有world.advance/routine内，单角色每次advance最多一次有限决策，纯候选计算与写入分开，无独立timer、render时重规划或无限重试。需要直接威胁避险时再补该consumer的小授权合同；**不要把公开查看的玩家1.25门套给内部规划，也不用等完整contacts闭合**。

持续状态需显式决策。`<24`进入、`>=36`结束需要可恢复intent；只看当前energy会丢迟滞，普通`behaviorState=rest`又无法区分疲劳／历史夜战状态。建议最小可选NPC记录，例如`routineIntent:{version:1,id,kind:'recover-energy',roleId:'carpenter',startedAt,goalEnergy:36}`，exact shape由ADR冻结；不是通用任务队列／执行框架。旧档缺省null、不造历史；reload重核唯一身份／岗位／职责，继续或取消但不补偿。writer/normalize/validator/replay须闭合，SAVE21加性策略须明确。若坚持无新保存域，应改为另一个无迟滞合同并承认reload重选，不用中文schedule前缀充当authority。

角色运动有碰撞而无完整寻路。实施前还须冻结有界“无法到达”处理：明确未到达，不记完成；有限停留后取消或原地恢复的政策只能择一如实呈现。不能无限重试、穿墙或把去居住区当安全保证。

## 让玩家能看见并改变

复用附近查看／名册已有schedule槽位，显示真实“当前安排／原因／恢复后做什么”，例如“精力不足，先回居住区休整；恢复后回工坊”。未到达时写“前往”，不能提前写已休整／已完成。支援接管后改为“例行安排让位于支援”。lastReport会被进食、感知、中继覆写，新解释应取结构化当前intent，不能把最近回执当实时计划。direct-sight新行和原普通toast清理保持。

只在真正开始／取消／完成时写一次原因、原world.advance因果；重复查看不发事件，持续执行不每分钟刷屏。旧workHistory／历史事件不追溯改。玩家可按原近身规则请求支援（真实2E／15分钟、拒绝与推进中死亡中断均保留），或公开等候观察返岗。暂不新增强制休息按钮或免费补能道具；未来“暂缓／恢复例行”另立控制合同。

## 最小基线比较与风险

未来比较需冻结23b8／候选、完整同writer、seed、公开时间输入，先单因素：

1. 核心pair：energy23.5/workClock59/simMoveClock15，先实际复现旧版矛盾，再验新取消→真实移动→恢复→返岗。分钟路径为主，大步差异另列，不顺手宣称全局等价。
2. 非触发与门边界：energy40不吞旧工作；23.999/24/35.999/36、中途reload、重复原command验证相应门。不能修改待测state来补完成。

4. 真实公开观察：同source-native输入，经地图／查看／名册／公开耗时动作记录开始、途中、返岗、刷新；只有trace没有运动与可读原因不算完成。

主要行为指标可先选“宣称恢复时仍指向工位或发例行completed的分钟比例”，另记返岗时长、切换次数、无法到达停留、原职责丢失和决策预算。先消除严重不一致，再用小pilot问“他为什么离开、何时回来、我怎样接管”，记录干预是否真实有效；不预设论文阈值或以自动存活率代替乐趣。
