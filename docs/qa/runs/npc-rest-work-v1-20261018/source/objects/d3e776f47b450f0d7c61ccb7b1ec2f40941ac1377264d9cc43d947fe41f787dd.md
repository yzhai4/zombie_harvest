结论：原命题部分成立。低精力木匠在同一真实分钟恢复精力、降低疲劳，仍移动并得到例行工作完成回执；但到达工作脉冲的分钟会把“休整”标签覆盖成“岗位工作”。另一个只少一分钟工作积累的派生场景，才实际保留“休整 · 精力恢复”与工作行为、向工位移动并存。不能将这两个终态合并描述。

## 授权、职责与让权边界

实际木匠为 role“木匠”、effectiveRole `carpenter`；真实 npcFulfillsRole/npcHasRole 均成立，唯一 effective carpenter 仍为其本人；camp-local、healthy、HP100，actingRole/garrisonedOutpostId 均 null、supportRequested false，dayNpcCanAttack false。relayProject 为 unknown，未占用中继工作；DAY、clock rate1 且未暂停。

源码实际顺序为 advanceReducer → updateNpcRoutine（需求、日程、运动目标、感知、SAN，最后工作脉冲）→ updateRelayProject → 敌人模拟 → 连续运动 → 日间战斗。campWorkPulse 对非本营、夜间、已请求支援、非 ready 有原有让权门槛。此次保持真实默认未占用状态，没有假造支援、relay 或战斗冲突来构造结果；它们在本次没有做行为变体检验。

原 memo 还需限定两处：木匠的 authored homeZone 是 workshop，不是 residence；workZone 是 eastGate，而工作脉冲另设 destination 为 workshop。主比较不能说终态仍指向 eastGate，也不能将未来“回居住地休息”方案写成现有事实。角色继任/双职政策、支援和中继让权的完整重设计不属于这三分钟证据。
