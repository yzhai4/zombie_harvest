# NPC口头侦察玩家pilot

状态：draft／尚未招募、未执行。关联[视线报告设计卡](../scripts/npc-direct-sight-observation-v1.md)、[调研落地计划](../research/research-adoption-plan-20261017.md)。原文E1–E8为待设计矩阵，本卡只承接可玩核心与信息可读性假设，不是生成模型对比，也不照抄报告样本／阈值。

假设：同一真实敌情下，附近NPC有来源的粗类别／距NPC距离报告，能帮助玩家决定先自卫、移动还是继续耗时行动；玩家能理解这是查看时的有限线索，未报告不代表安全。

工程前置限本消费者：真实公开查看、实际NPC感知与个人披露、两入口可见性、as-of生命周期、无额外资源／时间／地图揭示，冻结源码与输入。contacts、任意对象观察和完整记忆不是本pilot前置。先通过本片工程验收，未通过前不运行真人比较。

方法草案：同构建提供报告显示／不显示两种明确实验条件，保持世界事实与NPC实际行为相同；成对固定seed与初态，反转顺序并用不同但等价场景降低学习效应。参加者使用公开入口自由行动，研究员不提示敌人的位置或正确策略。正式执行前冻结场景、条件实现、人数与停止条件、主指标及提问方式；这些目前未确定，不宣称预注册。

记录分开：

- 客观事实：是否主动查看、查看后第一个有意义行动及其真实代价／后果、报告与当次授权事实是否一致、是否把NPC报告当作自动救援。不能把存活直接等同于正确选择。
- 可读性主问题：玩家能否用自己的话说明谁看到、何时看到、距离以谁为中心，以及没有报告是否意味着安全。
- 主观探索：是否帮助决策、是否愿意再次询问、agency／理解程度和干扰感；量表与主指标待pilot设计冻结，不自称已测PXI或BANGS。

判定：先依据观察修正文案和交互；若报告被理解为实时全局安全扫描，应暂停效果主张并修正，再重新冻结方法。小样本pilot只发现可用性问题和估计方差，不证明乐趣提升、正式统计效果、NPC规划收益或LLM价值。无人参与时只报告工程证据，不用agent或LLM judge冒充玩家。

后续E2规划、E3记忆、E4生成表达、E5跨副本、E6回放、E7exact与E8 learned shadow分别建立自己的比较；多主体sandbox另需单体可靠、通信预算、玩家干预和冲突后果合同。这里不把这些目标改成已完成。
