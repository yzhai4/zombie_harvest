# Leader LLM harness contract fixture (offline)

## Purpose

This is the first headless contract artifact for `ADR-20261014-leader-llm-harness`.
It covers only `ProjectionV1`, `IntentEnvelopeV1`, `GateReport`, and a deterministic
camp commander rules baseline. It is a negative-control fixture, not a runtime
adapter and not a content registration mechanism.

## Boundary checked against `dist/index.html`

The current HTML has the relevant production boundaries already in place:

- `ContentRegistry` exposes registered content kinds and `PLAN_DEFS`; plan meeting
  candidates are generated by `generatePlanMeeting`, and commitment goes through
  `dispatchCommand({ type: 'plan.meeting.commit', ... })`.
- `CommandBus.dispatch` allocates/replays command IDs, applies validation before
  the reducer, and records `command.rejected` or the resulting event in the event
  ledger. This is the only command path a future leader adapter may call.
- `registerEventDefinition` and `registerContent` are the existing registration
  boundaries. The harness checker does not import or modify either one.
- `WorldFacts.snapshot` / `WorldSnapshot.capture` expose the complete world to
  the local game today; `ProjectionV1` is intentionally a smaller allow-list for
  a future leader adapter. The fixture never serializes a raw save or hidden
  enemy/faction state.

The fixture therefore models a future adapter's input/output boundary without
claiming that production currently has a leader planner. No `dist/` file,
`SAVE21`, `CONTENT3`, server, or Sites artifact is changed by this check.

## Files

- `scripts/fixtures/leader-harness/projection-v1.json` — allow-listed commander observation.
- `scripts/fixtures/leader-harness/intent-envelope-v1.json` — valid baseline intent.
- `scripts/fixtures/leader-harness/world-baseline.json` — tiny deterministic Gate world.
- `scripts/fixtures/leader-harness/gate-report-baseline.json` — expected accepted receipt.
- `scripts/fixtures/leader-harness/intent-invalid-unsupported-command.json` — negative control for an unregistered/eval target.
- `scripts/fixtures/leader-harness/intent-invalid-hidden-field.json` — negative control for a `GameState` patch field.
- `scripts/check-leader-llm-harness.mjs` — standalone checker; it does not load the HTML.

## Run

```text
node scripts/check-leader-llm-harness.mjs
```

Expected result is six passing checks. The checker verifies unknown-field rejection,
projection hash freshness, fixed actor/role/phase and resource gates, stable plan
target IDs, registered-command-only dispatch, and deterministic rule fallback
metadata. A rejected intent produces a `GateReport` with a reason code and fallback
ID; it never mutates a world state or writes a replay entry.

## Exit criteria for a later adapter

Before connecting any model, add a separate headless adapter and replay fixture.
That work must preserve this checker, add idempotent `intentId` receipts, and prove
that `model-unavailable`/timeout paths invoke the same registered rules baseline.
Do not add a leader schema to an old save or wire this checker into the production
bootstrap as part of that work.
