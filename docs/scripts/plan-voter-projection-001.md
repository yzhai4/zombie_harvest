# 计划会票源与断粮观察投影（plan-voter-projection-001）

**状态：** 设计提案 / 待裁定；未实现、未完成验收  
**问题来源：** [PROB-20261014-plan-voter-projection](../problems/PROB-20261014-plan-voter-projection.md)  
**范围：** 真实英雄身份到计划会票源、食物状态到候选评分、每日会议快照；不修改晋升门槛或创造新角色  
**现有保存基线：** SAVE21 / CONTENT3；本卡不是新增 `EVENT_CHAIN_DEFS` 剧情实例。

## 来源与玩家承诺

规则源为 [06 NPC英雄晋升与普通NPC体系](../../剧本/尸潮农场/06_NPC英雄晋升与普通NPC体系.md)、[07 计划会与commandPoints](../../剧本/尸潮农场/07_计划会与commandPoints.md)；详细映射参考 [camp-plan-meeting-001](camp-plan-meeting-001.md)、[npc-promotion-001](npc-promotion-001.md)。01–09 的规则真相优先于旧剧本卡及实现中的临时 ID 特例；相互矛盾的段落在本卡列为待裁定，不能以测试更简单为由自行选择。

玩家应看到：已确认晋升的 NPC 能在新的计划会上表达岗位利益；仅满足晋升条件者仍是候选英雄；伤亡或拒绝使角色能力发生可解释的变化。食物真正耗尽时，候选应识别供给危机，而不能在“紧张”时加分、到“断粮”反而丢失危机信号。谁有票、为什么有这份权重、该票属于哪一次会议，应能由保存事实和账本解释。

本次只提出设计和测试契约，不把票源字段修正等同于完整自治、真实晋升试玩或饥荒平衡已经完成。

## 身份与可用性契约

以下是无冲突的目标边界，数值权重和伤病例外仍由后面的裁定表约束：

1. **身份单一真相：** 投票读取经现有 normalizer 处理后的 `npc.hero`。正式英雄使用已确认的 tier/status，不能凭 `progress=100`、eligible、`NPC_STORY_DEFS.promotedTier`、技能名称或 stale `npc.promotedTier` 获得正式票。
2. **初始身份：** commander、radio、doctor 的初始 promoted 状态来自既有角色定义和初始化；不要求补造一次晋升事件才能参加会议。
3. **普通与 eligible：** 可提供需求/岗位建议，但正式英雄票尚未产生。身份可用后只改变票源，不自动授予额外 commandPoints、主持权、军队或资源。
4. **死亡：** dead 角色不得成为新会议票源或执行岗位；无复活、补人或以代理人的 ID 复制死者权重。保存恢复不能把死亡英雄重新纳入。
5. **critical / injured：** 当前实现均减半；设计对重伤冲突，对受伤折减没有同样明确的统一条款。需保留真实输入并在裁定后给出明确数值，不能用“只测健康英雄”掩盖分支。
6. **失踪 / 离营：** 是设计要求，当前缺少完整正式状态。下一轮若接入，应先声明观察字段、保存默认值、人口/岗位映射和解除条件；不临时给对象加 boolean 后声称完整实现。
7. **拒绝：** 现有 `npc.orderRefused` 是一次高风险命令拒绝，不等于长期拒绝营地合作。不能以 `lastReport` 文本、任意旧拒绝事件或个人 trust 高低，永久剥夺全部投票权。全局/提案相关拒绝的作用范围、期限与恢复方式须先定契约。
8. **暂代岗位 / 据点：** `actingRole` 或 `garrisonedOutpostId` 不自行改变英雄身份；主持、票权及远端参与需分别定义。不能将守军在 campLocal 中缺席直接等同于死亡，也不能复制原岗位 NPC 的票。

异常的 tier/status 组合和旧档恢复须在 normalizer 契约中处理；直接判定 raw 对象不是保存兼容验收。新票源辅助函数不负责晋升，不产生 `npc.promotion.completed` 或任何奖励。

## 同日候选冻结与晋升生效时点

提出以下快照方案供裁定；它依据“同一 seed/day/contentVersion/ledger snapshot”一致、每日一个实例和既有历史可审计要求，不宣称当前已完全实现：

- `camp-plan-meeting-001:d<day>` 首次真实生成时投影当时的合法身份、可用状态、食物、危机和岗位建议，保存 candidates/ballots。同实例的 reload、普通重复 SUMMARY、额外同日遭遇不得重抽候选或抹除已提交决定；调试 force 不能混入正常玩家路径。
- **晋升在生成之前完成：** 新会议可读到真实 promoted 状态，按最终票权政策参与。
- **晋升在生成之后完成：** 获得身份资格，但不逆改该会议历史票；首次后续合法新实例投票时生效。不是在同日 force 重生会议来兑现票权。
- **身份失效：** 死亡/失踪/拒绝的 live Gate 立即禁止该角色执行相关岗位；历史 ballot 保留来源，不篡改已发生事件。是否另记 invalidation、调整有效票并重新排序未提交候选，或降级已有方案，属于 V6 裁定；任何调整都需可记录、确定性、保留 CP 消耗，不能无记录重投。
- **已经 committed / resolved：** 不得通过晋升、刷新或再打一场遭遇清空 playerAction/history，再收一次 CP 或重发效果。安全重新规划必须有独立、已批准的因果事件与幂等键。

冻结候选不等于冻结角色生命和需求。新会议也必须继续从现有固定 roster 与实时可用事实生成，不沿用一个可以造人的“选民列表副本”。

## 断粮投影、真实排序与机会成本

`foodSituation` 的四个现有状态为“充裕、稳定、紧张、断粮”，来源是实际 food/dailyNeed；dailyNeed 来自实际活动人口。投影必须复用该来源，不另写一套模拟库存，也不把 NPC 个体饥饿等同于营地 food=0。

当前低粮修正给 harvest 或 `plan-medical-rotation-001` 加9。最小缺口修正可以将不可达的“短缺”接到真实“断粮”，但这是既有 +9 政策的适用修复，**不能证明断粮时采集提案一定胜出**：当前 score≥30 后转为支持票，多个候选可能已全部达门槛，最后仍由 basePriority/ID 打破同票。

断粮优先的设计目标是让营地合理比较保命供给、防线与医疗，而不是强制“一断粮就选采集”。核心正在被围攻时，守门可能比立即外出取粮更重要；有重伤员时医疗有真实价值，无伤员且缺粮时无条件医疗加分是否合理仍待数值/需求政策裁定。任何改成 score 总和排序、阈值调低、必选采集或扩大医疗收益的方案都是投票规则/平衡变化，需要独立决策和回放版本，不混进字段修复。

候选卡须分别显示食物危机、支持理由、可行来源、岗位/路线风险与预期收益。评分或投票只是决策信息，不能直接生成粮食、药品、现有人口以外的采集队或免除夜战。

## 六视角合理性账本

| 视角 | 断粮与票源应如何合理解释 | 不允许的捷径 |
| --- | --- | --- |
| 势力 | 周岚可建议有现存关系、真实库存来源的交易；独立英雄身份决定正式票，不因缺粮创造河湾援军 | 虚构贸易资源、外援人口或用 faction 标签替代英雄确认 |
| 营地 | 断粮信号持续存在，权衡供给、守门与医疗；候选可行性与实际岗位/人口/材料一致 | 改标签后宣称真实排序已解决，或用 +9 评分直接发食物 |
| NPC | 晋升让岗位利益获得正式表达；eligible只给建议；伤亡/缺席/拒绝有可恢复规则 | 死亡投票、复制代理权重、无限期根据一次拒绝剥夺权利 |
| 玩家 | 看见身份、票权、冻结时点、危机原因与风险；晋升后的资格何时参与有明确解释 | 刷新重投、强制指定更容易通过测试的候选、重收 CP |
| 敌人 | 缺粮提升现有压力，外出补给暴露与防线机会成本仍存在；防御选择须有威胁理由 | 饥荒时绕过夜战、取消敌人或无成本取得供给 |
| 全局链 | 初始身份、晋升 completed、会议快照、失效与效果执行可因果对应；日实例只结算一次 | 用 stale promotedTier、eligible 或注册表未来层级制造已晋升事实；把三日低信任路线当成晋升/断粮证据 |

以下均为待执行矩阵，不是现有通过结果。预期数值与失效方案涉及 V1–V6 的行，在裁定前保持 pending，不选择方便的替代断言。

| 士官暂代主持 | 指挥官缺席、有/无晋升士官、候选主持者均不可复制死者票；独立权重按裁定 |
| 晋升在生成前/后 | 前者新会议可参与；后者历史ballots不逆改，在后续合法新实例生效；同日extra encounter/force不得抹掉决定 |
| 快照后死亡/伤病/拒绝 | 历史票不被篡改，live执行Gate生效；有效票调整/安全fallback及CP保留按V6裁定 |
| 食物边界 | 按foodSituation测试充裕/稳定/紧张/0粮及人口变化；非断粮状态不误触发，断粮不丢既有危机输入 |
| 断粮与重伤/迫近威胁组合 | 观察候选score、支持票、最终排序与执行可行性；不能把score+9等同于采集一定获胜 |
| 门槛饱和/同票 | 多候选已score≥30时，保留原排序与ID稳定性；需要改善真实优先度时单独审规则变更 |
| committed/resolved 重载与再生成 | 不能重收CP、重投或重发奖励；fixed input/seed/contentVersion记录一致 |
| 新定义缺失/未知NPC | 缺包安全降级，不造票源；注册了voteProfile不等于runtime已消费它 |

首先执行 HTML 的真实 normalizer、晋升、票源、评分、候选和保存恢复函数；fixture必须注明用途并与源码执行分开。浏览器用真实角色卡和计划会核对已确认晋升与冻结可见反馈；后期保存夹具标明fixture模式。普通三日低信任路线没有英雄晋升/断粮投票，不可替代这些场景。未来 headless 全局实验再比较多 seed/策略的供给存续、伤亡、计划分布与排序解释，不只优化一个容易通过的案例。
