# ADR：公开营地等候／休整与真实时间 v1

**状态：** accepted，已接入开发构建并按[本轮QA](../qa/camp-rest-20261017.md)验源码与公开浏览器夹具；真实hidden仍未验证，自然多日与生产部署未完成。  
**日期：** 2026-10-17。  
**设计基线：** SAVE21 / CONTENT3；开发 HTML `efe039775346f4ee34269495810d9d9e778603d2bfac26996ff5e0b884cd7f0b`，运行时来源 `68028d0763c3a5d02ed8db9638823f33069efd18`。实现后的字节和证据另绑定，不能继承此基线或旧日历跑分。  
**主题：** P0 有意义的时间推进。范围不含断粮完整改稿、Scenario boot、LLM、运输、人口扩容、引擎替换或自动每日尸潮。

## 问题与玩家承诺

现有公开 N／推进威胁入口只启动一次遭遇，报告关闭保持原日期。自然世界时钟约每 1200ms 推进 1 游戏分钟；劳动动作耗时，有限需求处理完后却没有明确、可取消的等候入口。通过反复训练填日历会改变士气、SAN 和守卫压力，不能据此说明自然节奏成立。

玩家在营地庇护所旁选择“等候／休整30分钟”或“等候／休整60分钟”，清楚地放弃这一段主动操作机会，让当前世界继续运行；能观察进度，随时取消。NPC 继续自己的生活，敌人继续接近，粮食仍被消费，午夜仍结算原来的后果。这个动作不保证安全、满体力、治愈或事件成功。

公开名采用“营地等候／休整”，避免把它描述成有无敌保证的睡眠。第一片只提供明确的30／60分钟，不提供“直接到下一天”或模糊的“至清晨”。如果以后增加目标06:00，必须另行定义当前恰为06:00时的含义和最长时长，不能默默延长成24小时。

## 已查实际调用路径

当前 `advanceReducer(minutes)` 的顺序是：实际日历推进 → 每日配给 → 跨日维护 → 玩家被动体力 → 外围暴露 → 玩家 SAN → NPC 需求／日程／工作 → 中继 → 持续敌人的感知与决策 → 连续运动 → 日间双向战斗 → HUD。`advance()` 经 `world.advance` CommandBus 留收据，并维护 schedule clock；`state.night` 时还会推进 phase clock。

这条路径确实包含近场运动和战斗，但大步不是许多小步的等价证明：敌人感知与 think 有各自脉冲；运动有 fixed-step 上限及余量合并；攻击在一次推进末端收集目标。不能把 `advance(60)` 或更大的末端结算当作60次完整过程。本合同采用每步 **1 游戏分钟**，保持现有调用顺序；不另做只增加作物或只恢复人物的快进器。未来若使用2–5分钟步长，须重新证明期间感知／移动／伤害／中断边界，不能只因自然 timer 存在5分钟上限就声明等价。

当前 shelter 旧交互会直接给予最多18体力、8HP、10SAN及降低25暴露，再推进20分钟。本动作是独立入口，**不得调用该整备 reducer、复制其奖励或把旧奖励循环作为等候实现**。旧整备的平衡另列，不在本合同中扩大。

## 开始 Gate 与地点

所有条件必须在统一命令的实际 reducer／Gate 检查；UI disabled 只是反馈。

| 条件 | 合同 |
| --- | --- |
| 会话 | `SessionController.isDay()`，未退出、未终局、玩家 HP>0；START、BATTLE、REPORT、LOSS、RECOVERY、SAVING、EXITING 都不可开始。 |
| 时钟 | `clock.rate===1` 且未 paused；不修改旧档 rate，不把不支持的 rate 当成1。 |
| 地点 | 玩家距实际存在、有效的 shelter 不超过当前公开 context 半径1.25；保存其稳定建筑 ID及开始位置。没有 shelter／已离开就拒绝。居住区只有区域标记，第一片不把它默认为同等庇护建筑。 |
| 时长 | 只接受整数30或60；不接受任意输入、负数、NaN、无界截止或自动连续预约。 |
| 并发 | 每个玩家最多一个活动休整；同一实例重复开始不延长目标，不累计两个 timer。 |
| 资源与人物 | energy=0、food=0、低SAN或受伤本身不禁止等候。界面须显示当前粮食、体力及风险。没有新增食物、药物、CP、信任或体力支付，也没有额外奖励。 |
| 危险 | 下节的近场／追击危险必须不存在；缺少可信危险字段时安全拒绝，不推定无敌人。 |

不设置“粮食≤0无法等候”的硬门：自然世界允许玩家停留，禁止这一选择会掩盖短粮的真实后果，并削弱玩家对时间的取舍。资源耗尽后是否补粮仍由玩家决定；新危机出现时交还控制权，而不是把等候变成免费生产或补给。

## 危险与注意力中断

每步前复查会话、位置、活动实例与危险；每步完整执行后复查后果。一次1分钟内已经发生的伤害、扣粮、死亡和事件保留，不回滚，不重放，不补偿。

1. **近场危险：** 活动敌人距玩家或 shelter 锚点不超过 **5格** 时拒绝／中断。5格是本轮保守设计值，非论文结论或已测安全阈值；不能依赖视锥背向、墙后暂不可见、NPC／塔可能帮忙而忽略已存在的近场敌人。
2. **追击危险：** 真实 AI 为 hunt／pursue 且追击目标是玩家，或真实 perception 对玩家的锁定仍在该敌种记忆期限内时拒绝／中断。不能从过期 targetId 推断永久追杀；也不能伪造感知让检查通过。未知敌种或无法约束的运动参数失败关闭。
   当前真实近场motion的hunt目标固定为玩家；pursue再核玩家goal或有效锁定。speedFactor缺失沿用实际默认1；存在时须为number、finite且在(0,1.12]内，兼容当前factory的1／1.12，拒绝字符串、null、0、负数、无穷与超界值；不修改敌人本身。
3. **伤害与存续：** 玩家受损、现场NPC受损／死亡、营地建筑真实耐久下降、核心或人口存续失效、营地崩溃等真实变化立即停止后续步，并报告粗原因。现有伤害系数、射程、LOS、岗位与 critical 政策保持；休整不提供新战斗豁免。
   每步前后重新取真实对象快照；camp-local NPC／建筑以前或后任一落在玩家／锚点5格内判为现场。读取本次新combat.damage.applied正伤害收据，防止先治疗后受伤被净HP掩盖；远端驻守者不因历史营地坐标算作本地受伤。步间伤害也在下步前核对。
4. **新事项：** 开始时记录当前未处理事件／活动episode身份。途中出现新未处理事件、身份发生变化的新episode或实际阻塞行动的事件／遭遇时停止；向玩家展示真实入口。已有可选未处理事项不一概禁止开始，否则初始事件可能永久封锁等候并迫使玩家选择支线。跨日仍未处理的同一事件不伪造成新事件，也不因等候自行完成。
5. **缺粮：** food降至0本身不是自动恢复或时间回拨理由，仍执行真实 NPC 需求、配给缺口与 collapse。若由此新建断粮episode，按“新事项”停止；若只是已有危机延续，保留后果和清楚预警。第一片不重写断粮选择、期限、藏粮或额外惩罚。
6. **主动操作与阶段：** 玩家取消、移动、攻击、采集、交互、建设或开始遭遇前先结束活动休整，再交由原公开命令处理；既有动作自己的 Gate 和代价不放宽。只读面板可以查看进度，不能暗中执行劳动。阶段离开DAY立即撤销休整的时钟所有权。

风险反馈可以显示“附近存在威胁”“仍被追踪”“出现新事项”“现场受损”，不显示本来未授权的远处敌人坐标、私人记忆或隐藏奖励。规则层可以保守拒绝，但它不等于已完成 ActorObservation 权限投影。

## 昼夜是两个维度

日历20:00–06:00仍可能处于 `SessionController.mode==='DAY'`。这时可按上述 Gate 等候，NPC 依据实际 hour 回家／恢复，持续敌人继续模拟。不能只因日历变晚就切 BATTLE、刷尸潮、关闭日间世界或重置清晨。

`state.night`／BATTLE 是已启动遭遇的战斗所有权。休整不能在该阶段调用 `world.advance`，也不能推进其 phase clock、清掉波次、改变 supportIds 或偷取遭遇奖励。真实报告关闭仍保留日历；关闭报告后可重新显式开始一个合法等候实例，没有自动续睡。

## 体力：兑现既有再生规则，修复分片损失

本轮同时修复现有 `recoverEnergy(minutes)` 的分片问题：旧实现对每次输入 `floor(minutes*3/60)`，自然1分钟tick及小步休整永远得0，和已有 `passiveRegenPerHour:3` 规则矛盾。不能用“休整不承诺恢复”掩盖这个既有目标，也不能给休整另加固定18体力代替它。

再生只按本次实际推进的世界分钟区间结算。设推进后时间为 `end=worldMinute()`、本次真实分钟为 `m`、已有每小时再生率为 `r`，新增体力为：

```text
floor(end*r/60) - floor((end-m)*r/60)
```

应用现有 max 上限，保留既有 rate 的合法配置语义；本公开动作第一片仅支持 clock.rate=1。对于默认3/hour，即每跨一个既定20分钟边界恢复1体力。60个1分钟与一次60分钟、30+30以及中间保存刷新应获得相同再生；不是按休整开始重新计时。满体力溢出不存成未来信用。

此修复不新增恢复余数保存字段、不在加载时追补以前因分片漏掉的历史体力、不回算旧动作或重发收据，也不把当前时钟更换为操作次数。没有新增 flat HP／SAN／food 奖励。已有 SAN 的30分钟时钟、安全营地自然漂移、NPC 休息系数、每日维护原有的玩家HP+12等仍可能产生真实变化，必须在前后账本标为既有时间后果；不能断言“休整期间绝无HP变化”，也不能把午夜HP变化记成新休整治愈。

## 单一时钟、半程与幂等

- 开始时清理 held movement／交互连发，并把自然 world timer 的推进所有权交给唯一休整 scheduler；原自然 timer 不并行消费同一段世界时间。休整不通过 `clock.paused=true` 冻结世界后伪造局部更新。
- 建议每200ms执行一份1分钟步进；具体调度间隔属于运行时常量，需记录在验收版本。每次回调最多推进一个步骤，不按真实卡顿补几十步，不建立未处理的异步命令积压，渲染可以节流。
- 开始、每步、取消／完成／中断都经统一 CommandBus，带实例ID、expected progress及真实因果关联。每个step先核实例和预期已消费分钟，再核预算，成功后才增加已消费水位。重复commandId、重复step或stale实例不能再次推进。
- 每步必须先预留本次外层与嵌套 `world.advance` 所需自动命令ID；MAX_SAFE耗尽在支付和推进前拒绝，不能先写成功进度再发现子命令无编号。拒绝不能伪造 `time.advanced`／完成收据。
- 取消是幂等终态，不回收已度过的分钟或已消耗口粮。半程中断明确显示“已等候X／30（或60）分钟”和原因；不能标记完成或自动补足余时。
  极端MAX_SAFE耗尽时，统一CommandBus也可能拒绝stop自动编号；清timer、释放owner和保存已发生前缀仍无条件执行，不伪造terminal receipt、不另造opaque编号绕过预算。这类前缀同异常崩溃处理，不能称已有完整结束日志。begin预检3个、step预检2个已知父／child编号，不承诺给未知未来命令永久预留。
- 隐藏页面、pagehide、退出、刷新、会话freeze都撤销scheduler ownership并checkpoint。可见后恢复普通世界时钟，休整余时不自动补进；既有后台追赶规则与本实例分别记录，不把它伪称休整进度。刷新后本会话控制器始终idle，必须重新显式开始；不把存档中的开始日志当作自动重启授权。

## 保存、旧档与回放合同

休整控制器为 **ephemeral会话控制器**，不新增SAVE字段、rest保存域、内容版本或第二套事件系统。会话中保留instanceId、开始／目标worldMinute、durationMinutes、appliedMinutes、shelter稳定ID、开始位置、已知pending身份及terminalReason；这些只控制当前scheduler与本次UI，不成为loader的另一份世界真相。

活动控制器须满足：duration为30／60；目标与开始差为duration；`0≤applied≤duration`；已消费分钟与本实例实际 `world.advance` 收据相符；锚点身份存在且可验证；实例／水位不能从客户端随意覆盖。最后一次会话summary可供当前UI解释，刷新后回idle，不无限增长实例列表。持久事实只使用已有writer保存的实际世界、clock、CommandBus与事件账本。

- 完整旧writer无需有休整字段；原人口、伤亡、资源、日期、已提交计划、episode身份、据点事实均保留。SAVE21／CONTENT3保持，恢复体力不回算历史。
- 记录真实 `camp.rest.started`、每步与关联 `world.advance`、`camp.rest.stopped` 及其因果身份。正常pagehide先取消并记stop，再请求保存；刷新仅加载真实writer中的已发生事实，控制器idle、不补时、不再生、不扣粮、不重新发奖。
- 异常崩溃可能保留started与部分steps而没有stop。这表示该实例未证实完成；不得在loader补造stopped日志、把余时重放或将其当作恢复任务。可从已有日志解释最后状态，日志窗口已截断时明确未知。是否曾产生且保存过一个步骤，只由实际保存与收据证明。
- 不新增rest保存域，因此本轮没有“rest字段missing与present-invalid迁移”假合同；已有世界／clock／账本坏块仍按现有strict backup／recovery规则处理，不为休整放宽验证。坏档、损坏clock.rate和主／备恢复应验证原规则保持。
- 既有回放golden若旧输入未触及恢复节拍，理应保持；若真实体力分片修复改变已有预期，须记录输入／前后差异及因果，不能为维持旧hash恢复错误公式。新轨迹包含休整意图、步骤、实际 `time.advanced` 与终态原因，保存投影和命令回放分别验证。

## 六视角合理性账本

| 视角 | 体验与因果 | 不允许的替代 |
| --- | --- | --- |
| 玩家 | 看见目标时间、已消费时间、库存、可取消与粗风险；选择交出主动时间换取真实既有恢复，并承担变化。 | 无敌睡眠、满血按钮、隐藏倍速、失败回档、用训练增益凑日期。 |
| NPC | 全部存活人口的需求、饥饿、配给、SAN、工作与休息时段继续；驻守者仍按既定远端需求合同，不能回营福利或重复劳动。 | 玩家休息导致NPC时间冻结、凭空增员、死者／离营者在营地劳动和作战。 |
| 营地 | 真实食物与维护照扣，作物按真实午夜长，岗位／计划／CP按既有水位一次；核心耐久和collapse独立于玩家HP。 | 把作物催熟当全面模拟，免除缺粮，重复每日产出或回补已花CP。 |
| 势力 | 时间本身不触发尚未实现的远端援助、交易、信任或运输收益；只执行已注册且实际到期的内容。 | 用“盟友送粮”叙述解释资源，驻守等于新生产人口。 |
| 敌人 | 原敌人感知、移动、追击、双向伤害和增援规则照常；每步危险检查给玩家可理解的应对机会。 | 清敌、削伤、停敌钟、视锥漏洞睡过攻击、因日历夜晚强制创建遭遇。 |
| 全局链 | 同一日历持续推进，午夜hook／episode／配给／计划可回放；新事项中断后玩家能决定是否处理。 | 直接改day/hour、把遭遇当一天、把未完成事项自动完成、重载自动补完剩余时间。 |

## 验收出口与保留问题

运行时与真实浏览器至少覆盖：安全30／60分钟、0体力、0粮食可开始并承担后果、位置／阶段／rate拒绝、开始危险、途中接近／追击／损伤、新事件／episode中断、已有pending可开始、取消半程、真实隐藏与刷新、双timer／连点／stale／ID预算、夜历DAY与BATTLE区分、午夜配给／upkeep／计划／作物／据点守军、真实旧writer和已有strict坏块处理保持。被动再生另验1×60／60×1／30+30／跨日／满值溢出／刷新区间，不只比控制器进度。

步进对照须运行真实 `advance(1)` 链，不自行镜像需求、敌人或恢复公式作为唯一oracle。实际renderer需有公开开始与取消控件、目标和进度可见，按钮在终态后恢复；DOM fixture不代替Chrome真实操作。所有证据绑定新HTML及runner字节，旧失败保留。

本合同完成后才可在新构建跑新档自然混合路线；静态smoke、派生午夜fixture、重复休整或旧训练三日均不自动证明新自然三日或好玩。真实到day4≥06:00、目标驱动行动、原十人／资源／伤亡账和失败／无目标时长仍按自然协议单列。断粮三策略的激励、继任双岗位、完整14日最终尸潮和Actor知识边界仍是独立未完成主题。

本次新增的是项目L1决策合同；没有修改全局记忆，也没有产生部署或生产通过结论。
