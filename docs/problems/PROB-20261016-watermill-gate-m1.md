# 水车支线条件解释分叉

**状态：** mitigated locally，待远端 CI 与浏览器复核  
**发现日期：** 2026-10-16  
**范围：** `watermill-002` 的启动、节点选择、UI 门控和内容 reducer

## 问题与影响

水车支线同时暴露旧的 `startConditions`/`requirements` 和新的条件对象。此前没有一个明确的公共 Gate 契约，启动链、事项面板和直接 resolver 调用可能得到不同答案：面板隐藏了按钮但公共入口仍可调用，夜间入口可能绕过白天限制；损坏或未知对象条件还可能被旧解释器当作满足。反过来，如果每次选择都重新应用启动条件，营地信任在链启动后下降会使已经承诺的故事突然不可结算。

这类分叉会产生三种可见后果：玩家看到的可选项与实际结算不同；夜间或自动化入口能执行白天内容；条件失败后资源、完成事实和事件账本可能留下半套状态。它也会让后续把内容迁到 `EventDef/EventInstance/Choice/Effect/Gate` 时无法判断哪个字段是真相。

## 根因

- 内容定义把日期窗口、启动条件和节点选择条件放在不同字段，缺少版本标记。
- UI 只做可见性判断，不能作为规则边界；resolver 仍有公开调用路径。
- 旧的对象条件解释没有统一的未知类型策略。
- 启动条件和已启动实例的运行时条件没有区分，信任变化的语义未被记录。

## 本轮修复契约

- `gateVersion: 1`/`evaluatePreconditions: true` 使内容链显式进入 GateV1。
- 注册器规范化并去重条件别名；未知或 malformed 条件 fail closed，且 Gate 只读。
- 启动检查地标、信任、日期窗口和白天阶段；选择检查白天阶段、内容窗口及本选择的 `requires`。
- 已启动的水车链不重复检查启动信任和地标；这样启动后的信任漂移不会破坏玩家已获得的选择承诺。
- 选择通过后仍由原 `content-effect` 事务 reducer 结算；本轮不改 `EventInstance`/CAS、效果 schema、保存版本或 Sites。

## 复核结果

`node scripts/check-content-chain.mjs` 通过 53 项真实源码夹具，覆盖：启动通过/拒绝、日期和夜间边界、未知启动条件无突变、未知选择条件在效果前拒绝、活动链信任漂移、旧字段兼容、修复/拆解奖励、回滚、重复、过期、缺包和中间节点恢复。来源命令轨迹为 `c5d6c772`；最终分支 HTML SHA-256 为 `bc85cbeab7f00236e7bde84f01d05596676b359fb66b077645103011810fb23d`。

## 剩余风险与后续

1. 这是 Gate-only 迁移；`EventInstance`、CAS、统一 `Effect` 以及跨内容 canonical 模块仍未完成。
2. 未知对象条件现在统一失败关闭，旧内容包若使用未登记类型会被锁住；应补注册类型和负向夹具后再扩展。
3. 本地可运行检查不能替代最终提交的 CI，也不能声称自然三日或完整浏览器回归；Sites 生产 v81 保持不变。

## 六视角合理性账本

| 视角 | 结论 |
| --- | --- |
| 玩家 | 启动时看到明确的水车、信任和日期前置；启动后信任下降不会收回已承诺的选择，夜间/过期会显示拒绝。 |
| NPC | 修复仍要求阿梁活动且由既有效果 reducer 执行；Gate 不会凭空让死亡 NPC 代修。 |
| 营地 | 零件、campCollapse 和 resonancePressure 只在效果事务通过后变化，Gate 失败不写资源。 |
| 势力 | 水车关系仍是内容设计关联，本轮没有伪造河湾互助会收益或外交状态。 |
| 敌人 | 拆解的共振压力仍写入既有 meter；本轮不宣称尸群公式已消费该值。 |
| 全局事件链 | 支线窗口和完成事实不阻塞中继主链；Gate、回滚和重复命令仍可回放。 |
