# 循环状态机与玩家自治规则

## 1. 状态和边界

世界状态稳定 ID：phase-day-001、phase-night-001、phase-summary-001。昼夜状态只能按 DAY → NIGHT → SUMMARY → DAY 迁移。暂停、隐藏面板、状态终端和对话窗口是 UI 标志，不是新的规则状态。

DAY 接受移动、采集、建造、修理、研究、制作、对话、事件选择、派遣、计划投票和存档。NIGHT 只接受移动、锁定目标、攻击、撤退和已经准备好的 NPC 自动行为。SUMMARY 接受阅读日志、确认结算和存档，不接受新生产或资源转移。

## 2. 状态转换

| 当前 | 命令 | 前置 | 结果 |
| --- | --- | --- | --- |
| DAY | commitNight | 计划无未验证效果、岗位快照成功 | 写入 nightPrepSnapshot，进入 NIGHT |
| DAY | endDay | 至少经过最小白天时长或玩家确认 | 运行自治、锁定资源并进入 NIGHT |
| NIGHT | resolveNight | waveBudget 已生成、实体预算通过 | 记录战斗、伤亡、建筑损伤 |
| NIGHT | finishNight | 所有阶段完成或失败 | 进入 SUMMARY |
| SUMMARY | acknowledgeSummary | summary effects 已幂等提交 | 增加 day，进入 DAY |
| 任意 | save | schema 和 checksum 通过 | 保存 currentPhase 与账本游标 |

所有转换失败都返回 reasonCode，不写入半套状态。night guard 必须在命令总线入口检查 phase，而不是依赖按钮隐藏。

## 3. 玩家行动与营地自治

玩家不是全知控制器。玩家可设置自治权重 autonomyWeights：defense、research、harvest、logistics、diplomacy，范围 0–100，总和自动归一化。权重只影响计划排序和 NPC 投票，不覆盖岗位能力、资源库存、疲劳和关系。

营地每个白天执行一次 plan-evaluate-001：

1. 读取库存、岗位空缺、建筑损伤、hordeForecast、压力、NPC 可用性。
2. 过滤不满足前置或缺少材料的计划。
3. 计算计划分数：priority + domainWeight + urgency + NPCVote - risk - laborCost。
4. 选取不超过并发计划上限的计划，写入 autonomy.effects。
5. 对未选计划写入 deferred 或 rejected 原因，供 SUMMARY 展示。

### 保守计划

稳定 ID plan-conservative-001。优先修墙、储水、治疗、补充基础食物和减少噪声。它不提前消耗 relayParts，不主动试种污染黑土；成功时 defense +6、campCollapse -2、研究进度不变，代价是 hordeForecast 提前量最多只有基础值。

### 冒险计划

稳定 ID plan-adventurous-001。优先中继、黑土试种、远端搜刮和提前制作脉冲装备。成功时 research/recon +8 或 food +20%，代价是 resonancePressure +3、疲劳 +2 或一栋外围建筑损伤概率上升。冒险计划必须有失败记录和次日补救。

### 玩家干预

玩家选择只能改变当前计划的优先级、资源承诺、参与 NPC 或路线，不能直接写成功结果。玩家亲自承诺时生成 commandId；执行仍由对应岗位、工时和材料决定。玩家未操作的节点由自治计划结算，choice 字段留空，autonomyResult 必填。

## 4. 岗位快照与自治降级

夜间快照包括人员、岗位、装备、建筑状态、弹药、计划、路线、诱饵和医疗资源。快照之后，白天状态变化不得影响本夜准备值。岗位可用性按 alive、health、fear、fatigue、roleSkill 和 distance 计算；缺席不补人。

| 降级层 | 触发 | 处理 |
| --- | --- | --- |
| A | 关键 NPC 缺席但有同岗位空闲者 | 使用现有岗位，效率 0.75 |
| B | 无同岗位但有普通劳动者 | 转为低效岗位，效率 0.5，并记录风险 |
| C | 无人口或岗位占用 | 计划暂停，保留已消耗材料 |
| D | 建筑损坏/占位冲突 | 使用临时覆盖或退守，不能凭空建造 |
| E | 夜间/过期/存档冲突 | resolveFallback，账本只写一次 |

## 5. 统一效果与幂等

状态变更必须使用 addResource、adjustMeter、modifyRelation、unlockTech、unlockWeapon、scheduleEvent、assignJob、damageBuilding、captureOutpost、recordHistory。每个批次有 effectId；应用前校验全部效果，任一失败则回滚该批次。重复 commandId、eventId、instanceId、effectId 返回 alreadyApplied，不再次扣除或发放。

## 6. 与 relay-chain-001 的交接

relay-chain-001 四节点仍由现有 EVENT_DEFS、QUEST_DEFS、NPC_EVENT_CHAINS 和 reducer 负责。本文只定义它在 14 日循环中的窗口：day04 可发现，day05 可交付，day06–09 可施工，day10 可上线。中继上线后只改变预测事实、路线和压力预算，不跳过最终尸潮。

## 7. 回放和迁移

回放输入为世界种子、日序、事件账本、玩家命令、自治权重和 nightPrepSnapshot。存档保存 currentPhase、day、contentVersion、SAVE_VERSION、ledger cursor、activeChains、completedChains、meters 和 history。缺少 autonomyWeights 时使用 defense 40、harvest 25、logistics 20、research 10、diplomacy 5，并写 save.migrated。
